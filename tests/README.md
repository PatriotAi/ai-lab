# tests — регресійні тести автоматизацій

**Відповідальність (одна):** довести **ділом**, що критична інфраструктура лабораторії
працює як описано — до того, як зміна потрапить у `main`.

## Навіщо
Автоматизації (`automations/`, `scripts/`) виконуються **в кожній сесії** й у розкладі,
але до 2026-07-21 не мали жодного тесту. Реальні баги, які вже коштували часу:
Stop-хук хибно позначав підписані коміти як «Unverified» (SSH-підпис + `%G?`), а рядок
`gpgsig` у **тексті** повідомлення міг замаскувати непідписаний коміт. Такі регресії
тихі — тест-джоб ловить їх автоматично.

## Запуск
```bash
bash tests/run-tests.sh      # локально; exit 0 — усі пройшли, 1 — є падіння
```
У CI: `.github/workflows/code-quality.yml` → джоб **`automations tests`** (на кожен PR).

### Окремо: браузерний прогін
```bash
node tests/mobile-agent-browser.mjs   # 61 перевірка в реальному Chromium (емуляція Pixel 7)
```
Наскрізний сценарій застосунку: ввід → відповідь → нотатка → пошук → перезапуск →
шифрування ключа → банер оновлення → PWA (manifest + service worker) → **робота без мережі** → **резервний контур**: 429 від провайдера → завдання в черзі → повтор → справжня відповідь; фатальний збій → видимий `failed` із ручним повтором; незавершене завдання переживає перезапуск; **замкнений ключ після перезапуску → очікування, а не деградація**; cooldown не б'є провайдера й не витрачає спроб; «тільки локальна» нічого не шле в хмару; застарілий прапорець очікування не заморожує завдання; `Retry-After` читається лише коли провайдер розкриває його через CORS (перевірено в обидва боки); сповіщення без тексту завдання (проводка, а не лише функція).
**Входить у `run-tests.sh` як секція 17** (з 2026-07-27). Доти тест існував,
працював і давав 29 перевірок — але не запускався **ніде**: ні в наборі, ні в CI.
Тест, який не ганяють, — це документація, а не перевірка.

Підключений із **трьома станами**, а не двома: якщо playwright/Chromium
недоступні, набір друкує `⊘ НЕ ГАНЯЛОСЬ` і показує це в підсумку окремим
рядком — але не червоніє (інакше CI без браузера падав би завжди).
Раніше сам тест виходив із кодом `0` за відсутності браузера, тобто
«не ганявся» зараховувалось як «пройдено» — рівно дефект F-2
(`docs/security/findings-2026-07-27.md`), який лабораторія вже лікувала
в `scripts/security-check.sh`.

## Правила написання тестів тут
- **Ізоляція обовʼязкова.** Кожен git-тест — у власному тимчасовому репозиторії
  (`mk_repo <name>`), який створює self-remote і **перевіряє**, що ми не в робочому репо.
  Викликати **без підоболонки**: `mk_repo x`, а не `d=$(mk_repo x)` — інакше `cd` не подіє
  і git-команди підуть у робочий репозиторій (спіймано на собі 2026-07-21: тести
  наробили сміттєвих комітів у гілці).
- Без мережі й без секретів. Залежності: `git` + `python3`; секція 6 додатково потребує
  `node` (у CI — `actions/setup-node`), і **пропускається**, якщо його нема.
- Кожен тест — одна перевірка, зрозуміла назва українською, звіт «очікували / отримали».
- Знайшов баг — фікс скрипта **і** тест-регрес на нього в тому ж PR.
- **Тест бере НАЙВАЖЧИЙ випадок у межах твердження, а не найзручніший.** Тест, написаний під
  формулювання, підтверджує формулювання, а не істину: перевірка омоглифів брала повноширинну
  форму, яку NFKC зводить, — і «проходила», доки кирилична літера лишалась незловленою. Питання
  до кожного тесту: «чи впаде він, якщо твердження хибне?» Якщо ні — це не тест, а ілюстрація.
- **Canary обов'язковий для будь-якого гейта.** Гейт без canary — сам неперевірене твердження:
  зламай навмисно (кожну перевірку окремо), переконайся, що спіймано, відкоти — має бути зелено.
  Canary ганяй на чистій функції з тимчасовим текстом, не мутуючи робочі файли.
- **Покриття canary визначає ПЕРЕЛІК ІНЦИДЕНТІВ, а не число.** «Canary ×3» — це число: три
  канарки чесно пройшли, а дірок було чотири. Випиши, які саме відомі способи помилитися гейт
  обіцяє закрити, і зроби канарку на КОЖЕН; число вийде саме.
- **Прогін на зламаному стані, не лише на чистому.** Перевірка, яка мовчить на чистому корпусі,
  ще нічого не довела. Візьми реальний старий стан (`git show origin/main:<файл>`) і переконайся,
  що перевірка ловить там справжній інцидент — саме так з'ясувалось, що перша редакція перевірки
  крос-посилань свій інцидент НЕ ловила.
- **Canary на робочих файлах — лише при чистому дереві.** Відкат через `git checkout --` повертає
  файл до HEAD і **стирає незакомічені зміни**: так було втрачено роботу цілої партії. Спершу
  коміт, потім canary; або працюй на копії.
- **«Порожньо» треба довести.** Зріз чи фільтр, що нічого не показав, може бути порожнім, а може
  відфільтрованим — на цьому вже спіймався фільтр `^[-+][-+]`, який тихо ховав рядки diff.
- **Тест бере НАЙВАЖЧИЙ випадок у межах твердження**, а не найзручніший: тест, написаний під формулювання, підтверджує формулювання, а не реальність (спіймано на собі 2026-07-26 — тест на омоглифи використовував повноширинну `ｉ`, яку NFKC зводить, замість кириличної `і`, яку не зводить).
- **Гейт без canary — сам неперевірене твердження.** Кожен новий детектор/гейт супроводжується перевіркою «навмисно зламав → спіймано; повернув → зелено».
