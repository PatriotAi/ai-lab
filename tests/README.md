# tests — регресійні тести автоматизацій

**Відповідальність (одна):** довести **ділом**, що критична інфраструктура лабораторії
працює як описано — до того, як зміна потрапить у `main`.

## Навіщо
Автоматизації (`automations/`, `scripts/`) виконуються **в кожній сесії** й у розкладі,
але до 2026-07-21 не мали жодного тесту. Реальні баги, які вже коштували часу:
Stop-хук хибно позначав підписані коміти як «Unverified» (SSH-підпис + `%G?`), а рядок
`gpgsig` у **тексті** повідомлення міг замаскувати непідписаний коміт. Такі регресії
тихі — тест-джоб ловить їх автоматично.

## Запуск
```bash
bash tests/run-tests.sh      # локально; exit 0 — усі пройшли, 1 — є падіння
```
У CI: `.github/workflows/code-quality.yml` → джоб **`automations tests`** (на кожен PR).

### Окремо: браузерний прогін
```bash
node tests/mobile-agent-browser.mjs   # 29 перевірок у реальному Chromium (емуляція Pixel 7)
```
Наскрізний сценарій застосунку: ввід → відповідь → нотатка → пошук → перезапуск →
шифрування ключа → банер оновлення → PWA (manifest + service worker) → **робота без мережі**.
Не входить у `run-tests.sh`: потребує playwright + Chromium. Якщо їх нема — **пропускається**
(exit 0), а не падає.

## Правила написання тестів тут
- **Ізоляція обовʼязкова.** Кожен git-тест — у власному тимчасовому репозиторії
  (`mk_repo <name>`), який створює self-remote і **перевіряє**, що ми не в робочому репо.
  Викликати **без підоболонки**: `mk_repo x`, а не `d=$(mk_repo x)` — інакше `cd` не подіє
  і git-команди підуть у робочий репозиторій (спіймано на собі 2026-07-21: тести
  наробили сміттєвих комітів у гілці).
- Без мережі й без секретів. Залежності: `git` + `python3`; секція 6 додатково потребує
  `node` (у CI — `actions/setup-node`), і **пропускається**, якщо його нема.
- Кожен тест — одна перевірка, зрозуміла назва українською, звіт «очікували / отримали».
- Знайшов баг — фікс скрипта **і** тест-регрес на нього в тому ж PR.
