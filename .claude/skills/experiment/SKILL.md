# experiment — запуск і ведення експерименту

## Призначення
Оформлює та веде маленький експеримент-гіпотезу за циклом методології
(`docs/methodology.md`): від гіпотези до висновку в `docs/learnings.md`.

## Коли застосовувати
- «Почни / новий експеримент», «перевіримо гіпотезу», «experiment».
- Треба швидко перевірити ідею наскрізним зрізом (vertical slice), а не будувати все.

## Кроки
1. Сформулюй **гіпотезу** (що покращуємо і чому) та **метрику успіху**
   (час / кліки / помилки / якість).
2. Створи теку `experiments/<slug>/` і `README.md` зі `templates/experiment.md`
   (slug — короткий kebab-case від теми).
3. Заповни **дизайн** — найменший наскрізний крок, не вся система.
4. **Запусти** й **виміряй**: занотуй результат і спостереження в `README.md`.
5. **Рішення:** лишити (промоутнути в `skills/` чи `automations/`) або прибрати.
6. **Висновок:** додай 3–5 рядків у `docs/learnings.md` за форматом журналу.
7. Якщо лишаємо — онови `docs/PLAN.md` і README відповідного каталогу.

## Приклади
- «Почни експеримент: чи прискорює `translate-uaen` двомовні релізи» →
  `experiments/translate-uaen-speed/README.md` з гіпотезою й метрикою.
- «Перевіримо гіпотезу про SessionStart-дайджест» → новий зріз + вимір + висновок.

## Нотатки
- Один експеримент — один наскрізний зріз; не роздувай обсяг.
- Завжди закривай висновком у `learnings.md` — навіть «прибрали» це теж результат.
- Для трекінгу можна завести Issue за шаблоном `.github/ISSUE_TEMPLATE/experiment.md`.
- Жодних секретів / PII у нотатках і даних експерименту.
