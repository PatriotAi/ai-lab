# content-pipeline — контент-пайплайн / content pipeline

## Призначення
Оркеструє повний цикл створення контенту: дослідження → чернетка →
двомовний артефакт (UA-канон + EN-дзеркало) → рев'ю. Делегує кроки
профільним навичкам (`deep-research`, `translate-uaen`, далі — `publish`).

## Коли застосовувати
- «Підготуй матеріал / статтю / пост / огляд на тему X».
- Потрібен повний шлях: тема → досліджений, вичитаний, двомовний артефакт.
- Для окремих кроків використовуй профільні навички напряму (одна навичка —
  одна відповідальність).

## Кроки
1. Уточни **тему, формат, аудиторію** і де лежатиме артефакт
   (`docs/`, `experiments/<slug>/`, окремий проєкт).
2. **Дослідження:** для глибокої теми — `/deep-research` (звужена постановка);
   для вузької — точковий пошук із 2–3 джерелами. Джерела фіксуй.
3. **Чернетка UA (канон):** структура — заголовок, теза, розділи, висновок;
   терміни звіряй із `docs/glossary.md`.
4. **EN-дзеркало:** через `/translate-uaen` (UA-секція перша, EN — дзеркалом).
5. **Рев'ю:** узгодженість термінів, перевірка фактів за джерелами,
   Markdown-розмітка, лінки.
6. Збережи артефакт; за потреби публікації — передай у `/publish`.
7. Якщо це експеримент — зафіксуй вимір і висновок у `docs/learnings.md`.

## Приклади
- «Підготуй двомовний огляд MCP-конекторів» → дослідження → UA-чернетка →
  EN-дзеркало → рев'ю → `docs/` або `experiments/`.
- «Контент-пайплайн: пост про SessionStart-хуки» → короткий пост UA+EN із джерелами.

## Нотатки
- Один прогін пайплайна — один артефакт.
- Джерела цитуй лінками; факти без джерела не публікуємо.
- Жодних секретів / PII у контенті.
