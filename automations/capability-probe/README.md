# capability-probe — профіль можливостей виконавця

**Відповідальність (одна):** на старті сесії з'ясувати, що виконавець уміє **нативно**
і що з цього **справді діє тут**, і подати це в контекст стисло.

## Навіщо

Правила лабораторії писалися для моделі-як-чорної-скриньки: не знаємо, що вона вміє
сама → інлайнимо все. Частина цих інструкцій дублює те, що харнес робить за
замовчуванням, і коштує токенів на кожному ході (інструкції живуть у кешованому
префіксі, тож перечитуються щоходу).

Проба не дає права **вірити**, що робота зроблена. Вона дає право **не повторювати
інструкцію** — за умови, що після виконання є перевірка, чи нативна поведінка
справді спрацювала.

## Чому це хук, а не правило в CLAUDE.md

ID моделі **недоступний як env-змінна** — він приходить лише в payload хука
(звірено на робочому харнесі 2.1.220). Payload також несе `agent_type` і `agent_id`,
тому профіль однаково працює на оркестраційному рівні й усередині кожного суб-агента.

## Як працює

```
payload хука (stdin)
  → scripts/capability-scan.py --hook-payload
      · знаходить РОБОЧИЙ харнес і доводить, що це саме він
      · один прохід по бінарнику на всі маркери (~0.4 c)
      · застосовує гейти → supported / effective / unknown
  → кеш за ключем (модель + версія харнесу + перемикачі + settings)
  → стислий профіль у additionalContext
```

**Кеш** — у `${XDG_CACHE_HOME:-$HOME/.cache}/ai-lab/profile-<key>.json`, поза репозиторієм.
Ключ не змінився → повторний скан не виконується. Змінилась модель, версія харнесу,
env-перемикач або `.claude/settings.json` → профіль пере-знімається сам.

## Три стани, а не два

| Стан | Значення | Наслідок |
|---|---|---|
| ✅ `effective=true` | можливість доведено діє тут | єдина підстава не інлайнити інструкцію |
| ❌ `effective=false` | харнес підтримує, але тут вимкнено | наше правило **обов'язкове** |
| ❓ `unknown` | гейт не змодельовано або харнес не впізнано | **повне правило**, skip заборонено |

`unknown` ≠ `false` і тим паче ≠ `true`. Будь-яка невизначеність → fail-closed.

## Ціна

Профіль потрапляє в кешований префікс, тобто перечитується кожного ходу. Тому:
- виводить **лише те, що змінює поведінку** — жодних таблиць і переліку невідомого;
- **мовчить повністю**, коли сказати нема чого (0 токенів);
- поточний розмір — ~490 символів (~160 токенів).

Проба, довша за інструкції, які вона дозволяє не інлайнити, з'їдає власну економію.
Це не стилістика, а умова корисності.

## Безпека

- Будь-яка проблема (нема python3, нема сканера, порожній payload, збій кешу) →
  **тихий вихід із порожнім профілем**, тобто повний набір правил. Хук ніколи не
  ламає старт сесії.
- Без мережі, без секретів, без запису в репозиторій.
- Невпізнаний харнес — єдиний випадок, коли проба не мовчить, а кричить: скорочувати
  правила на здогадці не можна.

## Активація

Ще **не зареєстрована** в `.claude/settings.json` — за планом Фази 8 реєстрація
відбувається лише після доказу економії (Етап C). Наразі запускається вручну:

```bash
echo '{"hook_event_name":"SessionStart","model":"claude-opus-5","agent_type":"root"}' \
  | automations/capability-probe/capability-probe.sh
```

## Перевірка

```bash
python3 scripts/capability-scan.py --validate   # 17 перевірок, у т.ч. на зламаному стані
bash tests/run-tests.sh                          # регресія автоматизацій
```
