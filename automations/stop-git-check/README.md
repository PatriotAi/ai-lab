# stop-git-check — індивідуальна перевірка комітів на Stop

**Відповідальність (одна):** наприкінці ходу сесії перевірити git-стан і
попередити лише про **справжні** проблеми: незакомічене/непушене та коміти,
які на GitHub справді будуть **Unverified**.

## Навіщо (корінь проблеми)
Базовий Stop-хук середовища Claude Code (web) міряв усі коміти одним правилом
«committer ≠ noreply@anthropic.com → тривога». Через це **серверні merge-коміти
GitHub** (натиснута власником кнопка Merge, злиття Dependabot) зчиняли фальшиву
тривогу й підбурювали *переписувати вже злиту історію* — що заборонено.
Рішення власника (2026-07-17): **не ігнорувати, а автоматизувати — рішення
щодо кожного коміта ухвалювати індивідуально.**

## Статуси підпису (%G?)
Прийнятні: **G** (добрий) · **U** (добрий, недовірений ключ) · **E** (локально
неможливо перевірити — так виглядають серверні підписи GitHub без ключа в
keyring). Неприйнятні: **N** (нема) · **B** (зіпсований) · **X/Y** (прострочений) ·
**R** (ключ відкликано).

## Класифікатор (по кожному коміту діапазону `upstream..HEAD`)
| Правило | Умова | Вердикт |
|---|---|---|
| R1 | committer `noreply@anthropic.com` + підпис прийнятний | OK (тихо) |
| R2 | коміт уже досяжний з `origin/main` | OK — спільна історія, не переписуємо |
| R3 | committer `noreply@github.com` + підпис прийнятний | OK — створено сервером GitHub (merge/squash через UI/API), на GitHub Verified |
| R4 | автор/committer `*[bot]*` + підпис прийнятний | OK — підписаний коміт бота |
| R5 | решта (без/зіпсований підпис, сторонній committer) | **FIX** — на GitHub буде Unverified |

Тривога (exit 2) — лише якщо є хоч один **FIX**; звіт містить вердикт і причину
по кожному коміту (друк обмежено 40 рядками, **скан завжди повний**), а порада
стосується **тільки FIX-комітів** (OK не чіпати).

## Стійкість (за підсумками рев'ю Codex на PR #20 — розібрано індивідуально)
- ✅ **C1** upstream більше не зашитий як `origin`: tracking-ref → `<remote>/<гілка>`
  → `<remote>/HEAD`; нерозв'язаний upstream і збій підрахунку = **fail-closed** (exit 2).
- ✅ **C2** суворі статуси підписів (див. таблицю вище) — зіпсований/прострочений ≠ OK.
- ⚖️ **C3 відхилено свідомо:** класифікатор вмикається лише при `commit.gpgsign=true` —
  у репо без підписування «Unverified» є нормою, тривога на кожен коміт зробила б хук
  нестерпним; хук боронить від регресій там, де підписування вже налаштовано.
- ✅ **C4** відірваний HEAD з локальними комітами → тривога (база: `<remote>/HEAD|main|master`).
- ✅ **C5** прибрано обрізання скану (`head -200`) — обмежується лише друк звіту.

## Активація
- Середовище Claude Code (web) виконує `~/.claude/stop-hook-git-check.sh`.
- Канон — цей файл; `scripts/setup.sh` ідемпотентно оновлює копію в `~/.claude/`
  (тільки якщо базовий хук існує і відрізняється).

## Тест без Stop-події
```bash
STOP_HOOK_TEST_RANGE="<base>..<head>" bash stop-hook-git-check.sh < /dev/null
```
Перевірено (2026-07-17): реальний кейс 10 серверних/ботових комітів → усі OK (exit 0);
непідписаний сторонній → FIX (exit 2); detached HEAD з комітом → тривога (exit 2);
клон із remote `upstream` (не `origin`) і непушеним комітом → тривога (exit 2, раніше
тихе 0); юніт статусів підпису G/U/E ✓ · N/B/X/Y/R ✗; штатні перевірки чистоти збережено.
