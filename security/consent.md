# Записана згода власника

Цей файл — єдиний легітимний спосіб пройти повз блок рівня R4.

**Навіщо він існує.** Гейт без виходу не робить систему безпечнішою: він робить
обхід єдиним способом рухатись далі, а обхід не лишає сліду. 2026-07-27 гейт
заблокував власного автора на зміні, яку власник уже прямо схвалив, — і єдиною
альтернативою було тихо переписати правила. Тому вихід є, але він **іменний,
датований і видимий у діффі PR**.

**Чесна межа — назвати прямо.** Цей файл редагує той самий агент, що виконує
дію. Отже це **не бар'єр, а реєстратор**: він перетворює невидимий обхід на
записаний. Для лабораторії з одним власником цього досить, бо кожен запис
потрапляє в рев'ю PR. Там, де сторін кілька, перевірка має жити поза агентом
(захист гілок, обов'язковий рев'ю, підпис коміта).

**Як читати таблицю.** `until` — дата, після якої запис не діє. Прострочений
запис гейт ігнорує мовчки, тобто згода не «залипає» назавжди. Щоб відкликати
згоду раніше — просто видали рядок.

**Ціль (з 2026-10-07, F-17; для кожного правила з `require_target` — з 2026-10-16,
W-12).** Ціль дії визначає гейт і показує її у відмові дослівно; рядок мусить
назвати її так само: `правило@ціль` (регістр не важить). Види цілей (списком, а
не таблицею: гейт читає як згоду кожен рядок файла, що починається з `|`):

- злиття PR через MCP — `owner/repo#N`: `mcp-merge_pull_request@patriotai/ai-lab#86`;
- інша MCP-дія — `[owner/repo:]ключ=значення`, ключі — `[mcp].target_keys` у політиці:
  `mcp-slack_send_message@channel_id=c1`;
- файл у цьому репо — шлях відносно репо, кілька — через `+`: `agent-settings@security/policy.toml`;
- файл в іншому репо через MCP — `owner/repo:шлях`: `workflows@o/r:.github/workflows/ci.yml`;
- `gh api` на запис — `метод шлях` або `post graphql:<мутація>`:
  `github-api-write@put repos/o/r/pulls/86/merge`;
- правило-команда — сама команда, пробіли зведено до одного: `merge-to-main@git merge main`.

Рядок без цілі таку дію **не відкриває**, рядок із ціллю не відкриває дію без
цілі, а дію, ціль якої гейт визначити не зміг, не відкриває **жоден** рядок —
тоді її виконують іншим каналом, де ціль видно, або власник сам. Ціль із
символом `|` у рядок таблиці не вміщається, тож така дія теж не відкривається.
Складену команду, що зачіпає КІЛЬКА правил R4 (`запис налаштувань && git push
--force`), не відкриває жоден рядок: згода на одну дію не має відкривати сусідню
(F-24) — таку команду розбивають на частини.
Раніше згода ключувалась лише на інструмент, і рядок «лише на PR #45» відкривав
злиття будь-якого PR до кінця свого строку: слова «лише на #45» читала людина, а
не код. Рядки нижче без цілі — історія, усі вони прострочені.

**`skill-surface@<назва навички>`** — той самий синтаксис для перевірки виконуваної
поверхні навичок (`scripts/check-skill-surface.py`): розширення прав чи скриптів навички
відкриває лише рядок із її назвою як ціллю.
