# Pre-Delivery Gate — v1.2.0 — автоматична перевірка перед видачею
> Пояснення — українською за замовчуванням (українською-перша); назви інструментів та ідентифікатори лишаються англійською.

## 🛡️ Протокол Збереження Перед Оновленням
Перед БУДЬ-ЯКОЮ зміною цього скіла — канон у `melania` (секції «Протокол Збереження» + «Update Workflow» + Core Rule 10).

## Що це і коли спрацьовує
Гейт запускається **АВТОМАТИЧНО перед КОЖНОЮ видачею** готового артефакту (скіл / оновлення / застосунок / файл / результат).

**Чесно про «автоматично»:**
- **У ЧАТІ** (тут): це жорстке ПРАВИЛО, якого Claude дотримується щоразу перед видачею (підкріплене governance `melania` + user-preferences). Це не код-хук — виконання через дисципліну Claude. Я НЕ можу технічно «заблокувати» сам себе кодом у чаті; я зобов'язуюсь пройти чек-лист.
- **У CLAUDE CODE**: жорстко через `skill_guard` hooks — код реально блокує доставку, доки перевірки не пройдено.

## ✅ Чек-лист гейту (УСЕ має пройти ПЕРЕД видачею)
1. **Валідація** — `validation-mesh` → вердикт **VALID** (не INVALID/UNKNOWN). Інакше — спершу полагодити.
2. **Безпека / IP** — `safety-compliance-gate` (особливо публікація / іменування за чужим брендом / untrusted вхід / монетизація).
3. **Тести** — `evals` присутні у **канон-схемі** (`name`+`assertions`+`version`) і концептуально проходять. Якщо evals нема — створити або явно зафіксувати причину.
4. **Guard** — `--snapshot`/`--validate` для скілів (структура не зламана, без усадки).
5. **Гігієна changelog** — версію піднято (bump) + запис у CHANGELOG; без непояснених дублів номерів версій.
6. **Доказовість тверджень** (Core Rule 14) — жодного фактичного твердження без тега [E]/[C]/[S] і жодного `[E]` без вказівника на перевірку. Механіка — `maintain.py verify`, методика — `validation-mesh` (Claim-Evidence Layer). Нема доказу → звузити формулювання.
7. **ПОВНОТА доставки** (маніфест) — перелічити ВСІ змінені артефакти й переконатися, що віддано КОЖЕН, а не вибірку. *(Запобігає «віддав 4 з 19».)*
8. **АНТИ-ВТРАТА стану** — `continuation-memory` snapshot + оновлення довготривалої пам'яті ключовими фактами/рішеннями. *(Запобігає втраті при стисненні контексту / перериванні сесії.)*
9. **Source + evals окремо** — для скілів: віддати source-теку з `evals/` ОКРЕМО (бо пакувальник виключає `evals/` з `.skill` → інакше тести губляться при install).

**Лише коли ВСЕ пройдено → віддати користувачу.** Якщо щось не пройшло — спершу виправити, потім видавати. Гейт не «косметичний»: він реально не пускає неготове.

## 🛑 Помилки, які гейт ЗАПОБІГАЄ (зібрано з реального досвіду)
| Помилка (що сталося) | Механізм запобігання |
|---|---|
| Втрата пам'яті/контексту при стисненні + перериванні | П.7: обов'язковий continuation-memory snapshot + довготривала пам'ять на кожному рубежі |
| Втрата напрацювань (evals «claimed-but-missing») | П.3+П.8: перевірити, що заявлені артефакти існують; віддавати source+evals окремо |
| Неповна доставка (показано частину файлів) | П.6: маніфест-перевірка — усі змінені артефакти віддано |
| Дрейф схеми evals (не той формат) | П.3: валідація канон-схеми `name`+`assertions`+`version` |
| Забуті перевірки (доки не нагадали) | Сам гейт — автоматичний runner усіх перевірок |
| Дублі версій у changelog накопичуються | П.5: гігієна changelog (bump + без непояснених дублів) |

## Область
Працює для **скілів, оновлень І аплікацій/артефактів**. Для майбутніх аплікацій можна спеціалізувати окремий профіль перевірок (напр. `app-delivery-gate`), що успадковує цей чек-лист.

## Координація (викликає, НЕ дублює)
ВИКЛИКАЄ: `validation-mesh`, `safety-compliance-gate`, `continuation-memory`. Для скілів — `melania` Pre-save gate + guard. Для пошуку втраченого перед видачею — `gsre-recovery`. Намір-роутинг — `semantic-router`.
