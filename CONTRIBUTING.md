# Внесок / Contributing

Тут працюють і люди, і AI-помічники (Claude Code тощо). Ці правила тримають простір
чистим, відтворюваним і безпечним.

## Базовий принцип
Працюємо експеримент-орієнтовано: **гіпотеза → запуск → вимір → лиши/прибери → висновок**.
Деталі — [`docs/methodology.md`](docs/methodology.md).

## Робочий процес
1. Працюй у гілці (не в `main`).
2. Один логічний крок — один коміт; повідомлення описове.
3. Перед комітом: `pre-commit run --all-files`.
4. PR за шаблоном; зв'яжи з issue/експериментом, якщо є.
5. Що лишаємо — виносимо в `skills/`/`automations/` і пишемо висновок у `docs/learnings.md`.

## Куди що класти
- Маленька гіпотеза → `experiments/<назва>/`
- Повноцінний проєкт-зразок → `projects/<назва>/` (старт зі `projects/project-template/`)
- Багаторазова навичка → `skills/<name>/SKILL.md`
- Хук/скрипт/пайплайн → `automations/`
- Утиліта → `scripts/`

## Безпека (обов'язково)
- Жодних секретів у репозиторії — лише `.env` (ігнорується) і `.env.example` без значень.
- Перед першим комітом: `pip install pre-commit && pre-commit install`.
- CI ганяє gitleaks, Trivy, Semgrep — не обходь їх. Деталі — [`SECURITY.md`](SECURITY.md).

## Для AI-помічників
- Спершу прочитай [`CLAUDE.md`](CLAUDE.md) і [`docs/methodology.md`](docs/methodology.md).
- Спілкування й документи — українською; ключові терміни дублюй EN.
- Перед великими/незворотними змінами — план (plan mode), тоді дія.
- Один скоуп — одна відповідальність; не змішуй кілька задач в одній автоматизації.

## Стиль
- Документація — Markdown, лаконічно, з прикладами.
- Іменування — зрозуміле, у стилі наявних файлів.
