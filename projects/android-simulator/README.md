# Віртуальний смартфон Android у хмарі

Перевірити застосунок Android (APK) або сайт **до того**, як ставити його на
справжній телефон. Уявіть «телефон напрокат у хмарі»: GitHub на кілька хвилин
вмикає віртуальний смартфон, ставить на нього ваш застосунок або відкриває
сайт у Chrome, тисне кнопки, фотографує екран, знімає відео і записує, чи щось
не «впало». Результат — сторінка зі знімками, яку зручно гортати з телефона.

> EN: Cloud Android phone simulator on GitHub Actions — run any APK/AAB or web
> page on an emulator and get screenshots, video, logcat and a crash summary.

## Статус
в роботі — перший робочий зріз (див. «Що перевірено»).

## Як користуватися (3 кроки, можна з телефона)

1. Відкрийте репозиторій на GitHub → вкладка **Actions** → зліва **Android simulator**
   → кнопка **Run workflow**.
2. У полі **target** вставте, що перевірити:
   - посилання на файл застосунку: `https://…/app.apk` (також `.aab`, `.apks`, `.xapk`);
   - застосунок з F-Droid за назвою пакета: `fdroid:org.fdroid.fdroid`;
   - збірку з іншого запуску GitHub: `artifact:<назва>@<номер-запуску>`;
   - адресу сайту: `https://…`.
   Оберіть пристрій (**phone** — звичайний телефон, **small** — маленький екран,
   **tablet** — планшет) і версію Android. Натисніть **Run workflow**.
3. Через 8–15 хвилин відкрийте запуск: угорі сторінки — **звіт** з вердиктом,
   анімацією (GIF), знімками екрана й посиланнями на відео та журнал.
   Зелена галочка — відкрилось і не впало; червоний хрестик — у звіті написано чому.

**Сценарій дій (необов'язково).** Щоб симулятор не лише відкрив, а й «потицяв»
потрібні кнопки, опишіть кроки у файлі сценарію [Maestro](https://maestro.mobile.dev)
(простий список: «натисни "Далі"», «прокрути», «зроби знімок») і вкажіть шлях у полі
**flow**. Приклади: `flows/app-smoke.example.yaml` (застосунок),
`flows/examples/think-like-gpt-tabs.yaml` (сайт: прохід по вкладках; у полі flow —
`sim:flows/examples/think-like-gpt-tabs.yaml`).

**Випадкові дотики (monkey_events).** Як дитина, що тицяє в екран: 300 випадкових
натискань шукають місця, де застосунок падає. Для сайтів вимкнено.

## Що ви отримуєте
| Що | Де |
|---|---|
| Вердикт (✅/❌), модель телефона, версія Android, розмір екрана | звіт на сторінці запуску |
| GIF-анімація перших ~90 секунд і знімки екрана | там само, картинками |
| Повне відео (до ~9 хв шматками по 3 хв), журнал системи (logcat), падіння | посилання у звіті + архів **Artifacts** (14 днів) |
| Коментар зі звітом у PR | якщо запуск пов'язаний з PR |

Картинки зберігаються в службовій гілці `android-sim-results` (лише останні 30 запусків),
бо GitHub показує картинки у звіті тільки за посиланням.

## Виклик з іншого репозиторію (наприклад, для PR і тестових копій Vercel)

```yaml
# .github/workflows/phone-preview.yml у вашому репо
on:
  deployment_status:
jobs:
  phone:
    if: github.event.deployment_status.state == 'success'
    permissions:
      contents: write        # покласти знімки в гілку android-sim-results
      pull-requests: write   # коментар у PR
      actions: read
    uses: PatriotAi/ai-lab/.github/workflows/android-simulator.yml@main
    with:
      target: ${{ github.event.deployment_status.environment_url }}
      device: phone
      flow: sim:flows/examples/think-like-gpt-tabs.yaml   # або шлях у вашому репо
    secrets:
      VERCEL_AUTOMATION_BYPASS_SECRET: ${{ secrets.VERCEL_AUTOMATION_BYPASS_SECRET }}
```

**Закриті тестові копії Vercel.** Тестові копії сайтів на Vercel закриті входом —
віртуальний телефон туди не залогіниться. Потрібен ключ «для автоматики» (одноразове
налаштування, ~3 хв):
1. Vercel → ваш проєкт → **Settings → Deployment Protection → Protection Bypass for
   Automation** → **Add Secret** (Vercel згенерує ключ) → скопіюйте його.
2. GitHub → репозиторій, з якого запускаєте (ai-lab для ручного запуску, або ваш репо, що
   викликає) → **Settings → Secrets and variables → Actions → New repository secret**:
   назва `VERCEL_AUTOMATION_BYPASS_SECRET`, значення — скопійований ключ.

Симулятор відкриває сайт із ключем, а знімки й відео робить уже з чистої адреси, тож ключ
на картинки не потрапляє. **Не вставляйте у поле target посилання з `_vercel_share=` чи
`x-vercel-protection-bypass=`:** GitHub друкує поля форми у відкритому журналі, тому
симулятор такі посилання відхиляє.

## Чесні обмеження
- **Немає входу в Google і Play Store.** Застосунки, яким потрібен акаунт Google,
  покупки чи сервіси Play, зупиняться на екрані входу.
- **Банківські й захищені застосунки** (перевірка Play Integrity, захист від копіювання
  відео — DRM, захист від «рут») часто відмовляються працювати на емуляторі. Це не помилка
  вашого застосунку — так вони захищаються.
- **Відеокарта програмна.** Важка 3D-графіка, ігри, WebGPU можуть не працювати або
  гальмувати; анімації — повільніші, ніж на телефоні.
- **Швидкість і пам'ять не як у конкретного телефона.** Емулятор показує, *чи працює й як
  виглядає*, а не *наскільки швидко* на вашому Samsung чи Xiaomi.
- **Процесор.** Віртуальний телефон — на процесорі x86_64. Застосунки, зібрані лише під
  ARM (більшість телефонів), система перекладає на льоту — але **не на кожній версії
  Android**. Перевірено на ARM-only застосунку SimpleX 7.1.3 (`chat.simplex.app`; на F-Droid
  лише збірки `arm64-v8a` та `armeabi-v7a`, мінімум Android 8.0), 100 випадкових дотиків:
  | Android (API) | Підтримує ARM-код | Результат | Запуск |
  |---|---|---|---|
  | 30 | так (`abi: x86_64,x86,arm64-v8a,armeabi-v7a,armeabi`) | встановився, запустився, живий, 0 падінь | [44377512305](https://github.com/PatriotAi/ai-lab/actions/runs/44377512305) |
  | 33 (типове значення поля) | ні (`abi: x86_64`) | **`INSTALL_FAILED_NO_MATCHING_ABIS`** | [44377495901](https://github.com/PatriotAi/ai-lab/actions/runs/44377495901) |
  | 34 | так (`abi: x86_64,arm64-v8a`) | встановився, запустився, живий, 0 падінь | [44381135113](https://github.com/PatriotAi/ai-lab/actions/runs/44381135113) |

  Висновок: застосунок лише під ARM на Android 33 не встановиться — оберіть 30 або 34.
  Типове значення поля **android** — саме 33, тож для таких застосунків версію треба
  змінити вручну. Це перевірено на одному застосунку; інші ARM-only застосунки на API 30/34
  не перевірялись. Рядка «Native code» на сторінці F-Droid не було видно — склад процесорів
  взято зі списку збірок кожної версії на сторінці й із самого APK (`native_abis` у вердикті).
- **Немає камери, GPS, SIM, датчиків, Bluetooth** — лише імітація або нічого.
- **Маленький екран** — це телефон з дисплеєм 720×1280 і щільністю як у компактних
  моделей, а не конкретна модель.
- **Тривалість.** Увімкнення телефона займає 2–5 хв; весь запуск — 8–15 хв хвилин GitHub
  Actions (для публічних репозиторіїв безкоштовно).

## Як це влаштовано (для цікавих)
- `.github/workflows/android-simulator.yml` — сам запуск: план → прогін(и) → звіт.
- `scripts/plan.py` — перевіряє поля форми (захист від підстановки команд) і складає план.
- `scripts/prepare-target.sh` — дістає APK (F-Droid / посилання / артефакт), AAB перетворює
  на APK інструментом Google `bundletool`, читає назву пакета.
- `scripts/run-on-emulator.sh` — на ввімкненому телефоні: встановлення, запуск, знімки,
  відео, сценарій Maestro, випадкові дотики, журнал.
- `scripts/report.py` — рахує падіння (crash) і зависання (ANR), пише звіт людською мовою.
- `scripts/publish-results.sh` — кладе картинки в гілку `android-sim-results`.
- `tests/` — самоперевірка скриптів (запускається на початку кожного запуску).
- Емулятор — `reactivecircus/android-emulator-runner`, образ `google_apis` x86_64 з
  апаратним прискоренням KVM.

**Безпека.** Секретів у репозиторії немає. Чужий APK працює лише всередині віртуального
телефона; крок, що має право запису (публікація картинок), не запускає нічого з цілі —
лише копіює знімки. Усі зовнішні дії закріплені точною версією (хешем).
