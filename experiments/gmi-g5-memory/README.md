- **Дата:** 2026-07-13
- **Статус:** чернетка — гіпотеза+дизайн, очікує підтвердження власника (крок 1)
- **Серія:** GMI · ітерація 2 (продовження `experiments/gmi/`, топ-прогалина G5)
- **Slug:** `gmi-g5-memory`

## 0. Звідки це
GMI-аудит System Core (`experiments/gmi/audit-systemcore.md`) дав топ-прогалину **G5 —
нема стійкого навчання між сесіями** (холодний старт; лише ручний `[АРХІВНА ВИТЯЖКА]`).
Ця ітерація закриває саме її — і робить це **догфудингом на власному кейсі** серії GMI.

## 1. Гіпотеза
Прогалину **G5** когнітивної системи можна закрити **явним зовнішнім циклом пам'яті**
*консолідація → індексація → витяг → оновлення* — **архітектурним шаром**, без зміни субстрату,
на наявних активах (`continuation-memory` + патерн `[АРХІВНА ВИТЯЖКА]`).

## 2. Метрика успіху (фальсифікована, вимірна)
«**Cold-start recovery**»: сесія, що отримала **лише зовнішню пам'ять** (без вихідного контексту),
відновлює **100% критичних пунктів** стану/рішень і робить наступний коректний крок **без повтору
вже зробленого**.
- Вимір: чек-лист критичних пунктів (рішення, відкриті нитки, наступний крок) → % відновлених.
- Провал = якщо cold-сесія дублює зроблене, губить рішення або не може продовжити.

## 3. Дизайн (найменший наскрізний зріз)
Vertical slice **на самій серії GMI** (реальний, не синтетичний кейс):
```
стан ітерації 1 (learnings + NEXT-ITERATION.md)
   │  консолідація → структурований memory-пакет (формат G5)
   ▼ experiments/gmi-g5-memory/g5-package.md
«cold-session» тест: відновити стан ЛИШЕ з пакета (без цього контексту)
   │  recovery-checklist → % критичних відновлено
   ▼ experiments/gmi-g5-memory/recovery-test.md
рішення: формат працює? → промоутнути протокол
```

## 4. Кроки (мапа на навички)
1. ✅ гіпотеза+дизайн (цей файл) → **пауза на підтвердження**.
2. ⏳ `continuation-memory` → сформувати `g5-package.md` (формат: стан · рішення · відкриті нитки · точний старт · recovery-checklist).
3. ⏳ **cold-start тест** → відновлення лише з пакета; `validation-mesh` звірка повноти → `recovery-test.md`.
4. ⏳ пере-аудит `gmi-audit`: чи G5 зрушив 🔴→🟡/✅ на цьому кейсі.
5. ⏳ рішення keep/prune + висновок → `docs/learnings.md`; за keep — промоутнути **G5-memory-протокол**
   (розширення `continuation-memory` або нова нотатка-стандарт) + онова `gmi-audit` (G5-чекліст).

## 5. Не-мета
- ❌ Не будуємо повноцінну пам'ять-БД / RAG-інфраструктуру.
- ❌ Не міняємо субстрат (це архітектурний шар, не залізо).
- ❌ Один зріз «пакет → відновлення → крок»; не автоматизуємо все підряд.

## 6. Рішення (keep/prune — крок 5)
- [ ] **Лишити → промоутнути:** якщо cold-recovery ≥ поріг → G5-memory-протокол у `continuation-memory`
      + G5-чекліст у `gmi-audit`.
- [ ] **Прибрати:** якщо відновлення ненадійне / формат не додає понад наявний `[АРХІВНА ВИТЯЖКА]`.

## 7. Ризики
- **Самореференційність тесту** (кейс = сам експеримент) → тримати recovery-checklist *об'єктивним*
  (перелік критичних пунктів фіксуємо ДО тесту).
- **Токен-бюджет** → пакет має бути стислим, але повним (та сама напруга, що й у G5 загалом — це і є предмет).
