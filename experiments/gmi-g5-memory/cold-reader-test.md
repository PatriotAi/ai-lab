# gmi-g5-memory — Cold-reader тест G5 (нитка T7, об'єктивний)

- **Дата:** 2026-07-14 · **Метод:** ізольований субагент (`general-purpose`, `run_in_background`),
  **0 звернень до файлів** — справді «холодний» читач (на відміну від само-аудиту в `recovery-test.md`).
- **Вхід:** рівно те, що видає авто-витяг `g5-retrieve` (§STATE/§DECISIONS/§OPEN THREADS/§NEXT STEP).
- **Завдання:** відновити розуміння + назвати прогалини + оцінити впевненість продовження 0–100%.

## Результат
| Що | Оцінка |
|---|---|
| Впевненість продовження з ЛИШЕ пам'яті | **~55–65%** |
| Розуміння стану + governance («не нашкодити») | ✅ достатнє |
| Розуміння **ядра** (що означають G1–G7, P1–P7, шкала 🔴/🟡/✅, [S]/RQM/vertical slice) | ❌ бракує |

**Чесна корекція:** попередній `recovery-test.md` показував «9/9» — це був **само-аудит** (я вже знав
терміни), тож **завищений**. Об'єктивний холодний субагент виявив, що пам'ять передавала *стан*,
але не *значення*. Це і є цінність незалежного тесту.

## Прогалини, які назвав холодний читач → дія
1. G1–G7 не розкриті → **§0 KEY-глосарій** (1 рядок на інваріант).
2. P1–P7 не розшифровані → у §0 KEY.
3. Критерії шкали 🔴/🟡/✅ не пояснені → у §0 KEY.
4. Скорочення/лінзи ([S], RQM, vertical slice) + шляхи до первинників → у §0 KEY.
5. P2-нитки без критерію «готово» → додано критерії в §0 KEY.

## Виправлення (застосовано)
- `g5-package.md`: додано **§0 KEY** (глосарій + шкала + скорочення + шляхи + критерії P2).
- `scripts/g5-retrieve.py`: `KEY` додано у `WANT` → глосарій тепер **авто-витягується** в кожну сесію.

## Очікуваний ефект і ре-валідація
Додавання ядра має підняти холодну впевненість до **~85–90%** (ціль T7). **Ре-валідація** —
повторний cold-reader субагент на оновленому пакеті; запускається за наявності квоти сесії.
*(Статус T7: виконано перший раунд + виправлення; ре-валідація — за бажанням.)*
