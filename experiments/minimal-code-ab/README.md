# Експеримент: драбина мінімального рішення (A/B)

- **Дата:** 2026-11-27
- **Статус:** чернетка (дизайн; прогін — окремою хвилею за згодою власника на витрату)
- **Гіпотеза:** секція «Драбина мінімального рішення» (`surgical-code-refactoring` v1.7.0,
  харвест Ponytail) зменшує обсяг нового коду й витрату токенів, **не** знижуючи частку
  прихованих перевірок, що проходять, і **підвищує** частку нетривіальної логіки з тестом.
- **Метрика успіху (заморожена до прогону):**
  - рядки diff (додані + видалені) — менше щонайменше на 20 % (медіана);
  - токени на задачу — не більше, ніж без секції;
  - приховані перевірки (тести, яких виконавець не бачить) — не нижче, ніж без секції;
  - частка нетривіальної нової логіки з тестом — вища;
  - рядок «що пропущено / не перевірено» присутній у ≥ 90 % здач.
  Провал будь-якої з перших трьох — секцію переглядаємо або знімаємо.

## Дизайн (найменший крок)
8–10 задач із реального коду лабораторії (`scripts/`, `automations/`) і одного проєкту:
баг-фікс, мала функція, правка з кількома викликами, «зроби гнучко на майбутнє» (пастка на
переускладнення), задача з межею довіри (пастка на «ніколи не скорочуй»). Кожна задача —
двічі тим самим класом моделі: **A** — навичка без секції (v1.6.1), **B** — з секцією (v1.7.0).
Порядок A/B випадковий; приховані перевірки пишуться ДО прогону й не показуються виконавцю.

## Кроки
1. Зафіксувати набір задач і приховані перевірки (пре-реєстрація, коміт до прогону).
2. Прогнати A і B суб-агентами одного класу в ізольованих гілках.
3. Порахувати метрики скриптом (`git diff --stat`, usage, прогін прихованих перевірок).
4. Висновок у `docs/learnings.md`; рішення лишити/прибрати секцію.

## Рішення дизайну і незворотність
- **Секція в навичці до виміру.** незворотність: `reversible` — це лише текст; провал пілоту → видалити секцію з bump і записом у CHANGELOG.
- **Чужий код не запускається.** незворотність: `reversible` — переносимо лише правила; плагін і хуки Ponytail не встановлюються.
