# Експеримент: gmi-g5-auto — авто-консолідація пам'яті (G5 🟡→✅)

- **Дата:** 2026-07-13 · **Статус:** у роботі (крок 2 — детермінований скрипт) · **Серія:** GMI · ітерація 3
- **Продовження:** `experiments/gmi-g5-memory` (G5 🔴→🟡) — тут знімаємо «ручний» бар'єр до ✅.

## Гіпотеза
G5 сягне **✅**, якщо **консолідація стане автоматичною**: детермінований скрипт (без AI/секретів)
регенерує стан пам'яті з `git` на межі сесії — прибираючи ручний крок «редагування пакета».

## Метрика успіху
Запуск скрипта → `AUTO-STATE.md` **точно** відображає HEAD/останні коміти й файли, **без ручних правок**;
цього стану достатньо, щоб cold-сесія відновила «де ми» (реюз recovery-ідеї ітерації 2). Провал =
скрипт неточний / все одно потрібне ручне доведення.

## Дизайн (найменший зріз)
```
scripts/g5-consolidate.py <experiment_dir>
   │ git log(dir) + список файлів + HEAD sha + час  (детерміновано, без AI)
   ▼ <experiment_dir>/AUTO-STATE.md   (авто-консолідований стан)
[gated] Stop-hook → авто-запуск на межі сесії  (торкається .claude/settings.json → згода власника)
```

## Кроки
1. ✅ гіпотеза+дизайн (цей файл).
2. ✅ `scripts/g5-consolidate.py` — детермінований генератор `AUTO-STATE.md`; протестовано.
3. ✅ Stop-hook `automations/g5-consolidate/` + `.claude/settings.json` (авто-тригер) — за згодою власника.
4. 🟡 пере-аудит `gmi-audit`: **консолідація тепер авто** (не ручна) → G5 з 🟡 **до ✅ у частині консолідації**;
   повне ✅ = коли hook стабільно спрацьовує в рантаймі (залежить від середовища) + авто-**витяг** (окрема нитка).
5. ⏳ keep/prune + висновок → `learnings.md`; за keep — узагальнити автоматизацію на будь-яку теку.

## Не-мета
- ❌ Без AI/секретів/мережі у скрипті (детермінований зріз, як `weekly-digest`).
- ❌ Не авто-**витяг**/навчання (це G5 повний цикл) — тут лише авто-**консолідація**.

## Рішення (keep/prune — крок 5)
