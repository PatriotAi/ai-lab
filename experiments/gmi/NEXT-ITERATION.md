## Наступна ітерація — гіпотеза й дизайн (готові до інтеграції)
**Назва:** `gmi-g5-memory` — закриття прогалини G5 (навчання/пам'ять між сесіями).

**Гіпотеза:** прогалину G5 когнітивної системи (нема стійкого навчання між сесіями) можна
закрити **явним зовнішнім циклом навчання** *консолідація → індексація → витяг → оновлення*,
збудованим на наявних активах лабораторії (`continuation-memory` + протокол `[АРХІВНА ВИТЯЖКА]`
System Core) — **без зміни субстрату**, лише архітектурним шаром.

**Метрика успіху:** нова сесія, отримавши лише зовнішню пам'ять (без вихідного контексту),
відновлює ≥ ключові рішення/стан попередньої й продовжує задачу без повтору вже зробленого
(вимір: чек-лист відновлених пунктів; ціль — 100% критичних).

**Дизайн (найменший зріз):** vertical slice на самій цій серії GMI —
`continuation-memory` пакет (цей файл) → «нова сесія» читає його → відновлює стан → робить
наступний конкретний крок (напр. G7 commit-протокол) без втрати. Тобто **догфудимо G5 на власному кейсі**.

**Мапа на навички:** `experiment` (скаффолд `experiments/gmi-g5-memory/`) → `continuation-memory`
(механіка пакета) → `gmi-audit` (пере-аудит: чи G5 зрушив 🔴→🟡/✅) → `validation-mesh` (звірка відновлення).

**Не-мета:** не будуємо повну пам'ять-БД; не міняємо субстрат; один зріз «пакет→відновлення→крок».
