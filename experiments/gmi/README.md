## 0. Контекст і чому саме зараз

Серед завантажених матеріалів — не просто тексти, а **діючий екземпляр**
«загальної системи мислення»: мета-промпт **«Гіперрозум / System Core v1.2»**
(роль PhD-brainstorming, first-principles, епістемологічний стек Рівні 0–2,
фазове дерево дослідження 1–5, **протокол пам'яті** «стиснення+індексація →
[АРХІВНА ВИТЯЖКА]») та дві його демонстрації в дії (походження часу як
самоорганізація інформації; вихрова гравітаційна система) + консолідований
`Research_Archive_v001`.

Отже GMI для нас — **не абстрактне «що таке інтелект»**, а конкретне питання:
чи є цей власний артефакт користувача когерентним екземпляром «загальної
моделі інтелекту», і що дає його звірка з усталеними рамками. Це дає
експерименту **емпіричний якір** (grounding case) і рятує від нескінченного
філософського огляду.

> Термінологія (зафіксовано власником 2026-07-13): укр. канон —
> **«Загальна Модель Інтелекту»**; EN-дзеркало — *General Model of Intelligence*;
> абревіатура **GMI**. Занести в `docs/glossary.md` на кроці 5.

## 1. Гіпотеза

Розбита на дві залежні частини — **означувальну** і **прикладну**.

**H-A (означувальна, головна).**
Крізь основні сімейства рамок — *AGI-визначення*, *теорії інтелекту*
(психометрика/g, множинний, триархічний), *world-models*, *cognitive
architectures* (SOAR, ACT-R, Global Workspace, Free Energy Principle) —
проходить **мала множина повторюваних функціональних інваріантів** (≈5–8),
яка й конституює «загальну модель інтелекту». Тобто GMI **означуване як
інваріантний набір**, а не як властивість однієї конкретної рамки.

**H-B (прикладна, grounding).**
Власний артефакт користувача **«Гіперрозум / System Core»** є *частковим
екземпляром* цього GMI-набору: відображення «інваріант → механізм у System Core»
покаже, **що він реалізує, а що — ні** (перелік прогалин, придатний до дії).

**Робочий (провізорний) кандидат-набір інваріантів** — те, що саме
перевіряємо/уточнюємо на кроці 2, а не готовий висновок:

| # | Інваріант | Одним рядком | Слід у рамках | Слід у System Core |
|---|-----------|--------------|---------------|--------------------|
| I1 | **Модель світу** | внутрішнє передбачувальне представлення середовища | world-models; FEP-генеративна модель; ACT-R declarative | епістемологічний стек, «карта знань» |
| I2 | **Ціль / корисність / агентність** | спрямована поведінка, вектор цінності | RL-reward; AIXI-utility; goals у cog-arch | «мета-гіпотеза», вибір вектора H2 |
| I3 | **Абстрагування** | багаторівневе виділення патернів | g-фактор; ієрархія ознак | «багаторівнева абстракція», TRIZ |
| I4 | **Висновок і планування** | пошук/інференс над моделлю | SOAR problem-spaces; планувальники | фазове дерево 1–5, розгалуження гілок |
| I5 | **Пам'ять та інтеграція знань** | стиснення, індексація, витяг | ACT-R; зовнішня пам'ять | **протокол «стиснення+індексація»**, Master Index |
| I6 | **Навчання / адаптація** | оновлення від зворотного зв'язку | FEP-мінімізація похибки; RL | критична фальсифікація, peer-review-цикл |
| I7 | **Метакогніція / саморефлексія** | моніторинг і самокорекція | Global Workspace; self-model | правило «постійний самоаналіз контексту» |
| I8 | **Генералізація / перенос** | застосовність між доменами | ядро «general» в AGI | той самий Core → час *і* гідродинаміка |

> Ці 8 — гіпотеза, а не результат. На кроці 2 їх треба **звузити/спростувати**:
> частину злити, частину відкинути як не-інваріантну, решту прив'язати
> джерелами. Цільовий фінальний набір — **5–7** інваріантів.

## 2. Метрика успіху (критерії, а не «відчуття»)

Це знаннєвий експеримент, тож метрики — про **строгість і придатність**, не про час:

1. **Покриття** (режим **deep-research**, обрано власником). Опрацьовано ≥4 різні
   сімейства рамок (AGI-визначення; теорії інтелекту; world-models; cognitive
   architectures), у кожному **≥3 фактчекнуті ключові джерела, первинні за
   можливості** (deep = ширший набір, а не «по два на галочку»).
2. **Крос-валідація інваріантів.** Кожен інваріант фінального набору
   простежується у **≥2 незалежних рамках** (інакше він не «інваріант», а
   артефакт однієї школи). Перевірка — через `validation-mesh`.
3. **Чесна фальсифікація.** Зафіксовано **≥1 реальну спробу зламати** набір:
   рамка або контрприклад, який *не* лягає в інваріанти (наприклад,
   вбудований/embodied інтелект без явної «моделі світу»). Результат
   документуємо навіть якщо він псує гарну картинку.
4. **Grounding-мапа.** System Core відображено на фінальний набір із **явним
   переліком прогалин** (що не реалізовано / реалізовано слабко).
5. **Двомовний артефакт.** UA-канон + EN-дзеркало (`translate-uaen`), пройдений
   `pre-delivery-gate` перед видачею.

**Поріг «успіх»:** виконано критерії 1–5 і набір інваріантів **пережив**
фальсифікацію (п.3) у вигляді уточнення, а не колапсу.

## 3. Не-мета (out of scope — щоб не розповзлося)

- ❌ Не будуємо AGI і не «вирішуємо» свідомість/природу часу (це був лише
  *домен-демонстратор* у джерелах, не предмет).
- ❌ Не робимо CFD/фізику вихрових рушіїв — вихрова система цікава нам винятково
  як *приклад переносу* (I8), не як інженерна задача.
- ❌ Не вичерпний академічний огляд усіх теорій інтелекту — беремо
  репрезентативний зріз, достатній для крос-валідації інваріантів.
- ❌ Не оцінюємо «правдивість» метафізичних гіпотез H0–H2 із джерел.

## 4. Дизайн (найменший наскрізний зріз)

Один вертикальний зріз **означення → інваріанти → один grounding-кейс**, а не
велика система:

```
джерела (4 сімейства рамок + власний артефакт користувача)
      │  source-research-harvest / deep-research  (крок 2)
      ▼
факти + ключові джерела (фактчек)
      │  knowledge-synthesizer  (крок 3) — неочевидні зв'язки → набір інваріантів
      ▼
кандидат-набір 5–7 інваріантів + спроба фальсифікації
      │  validation-mesh  (крок 3) — крос-валідація ≥2 рамки/інваріант
      ▼
grounding: System Core → інваріанти (мапа + прогалини)
      │  content-pipeline + translate-uaen  (крок 4)
      ▼
двомовний артефакт UA/EN  →  (за бажанням) publish / Claude Artifact
      │  pre-delivery-gate
      ▼
висновок → docs/learnings.md; онова docs/CONTEXT.md + glossary  (крок 5)
```

**Артефакти експерименту (структура теки):**
```
experiments/gmi/
├── README.md              ← цей файл (гіпотеза + дизайн)
├── sources.md             ← крок 2: джерела + фактчек-статус
├── invariants.md          ← крок 3: набір інваріантів + крос-валідація + фальсифікація
├── grounding-systemcore.md← крок 3–4: мапа System Core → інваріанти + прогалини
└── artifact/              ← крок 4: двомовний UA/EN артефакт (+ прев'ю за бажанням)
```

## 8. Ризики / антипатерни / рішення власника

**Ризики:**
- **Ризик розповзання** — тема безмежна; тримає §3 (не-мета) і поріг 5–7 інваріантів.
- **Ризик confirmation bias** — набір може бути «підігнаний» під System Core;
  контрзахід — обов'язкова фальсифікація (критерій 3) *до* grounding.
- **Ризик глибини** — deep-research → більший обсяг; тримаємо тими самими
  порогами (5–7 інваріантів, §3 не-мета), ширшаємо джерела, не тему.

**Рішення власника (зафіксовано 2026-07-13):**
1. **Назва:** канон **«Загальна Модель Інтелекту»** (EN: *General Model of Intelligence*).
2. **Глибина кроку 2:** **deep-research** (ширший, довший прохід; ≥3 джерела/сімейство).
3. **Публікація:** рішення відкладено — оберемо на **кроці 4** (файл у репо vs Claude Artifact).
4. **Стан гіпотези (пункт 1):** *очікує* — 1a (рушаємо) / 1b (звузити інваріанти
   разом) / 1c (переробити постановку).

**Робочий контракт:** перед кожним кроком — «потреба → інструмент → що треба
від власника», далі дія; незворотнє (зовнішня публікація, PR, merge у `main`) —
лише за явною згодою власника.
