# Model-Fit Policy (для ai-core-runtime)

> **Канонічне джерело — не дублювати тут:** `rlm-harness/references/model-fit-policy.md`
> (профіль КРОКУ → клас моделі, стратегії маршрутизації, бюджетний губернатор,
> quality-measurement caveat, анти-патерни).

ai-core-runtime застосовує ту саму політику для активації агентів/кроків рантайму:
- профіль кроку (reasoning-глибина · латентність · контекст · модальність · вартість · приватність · tool-use · незворотність) → клас моделі;
- дефолт **cost-then-quality**; **cascade** при провалі валід-гейта; **quality-first** для незворотних/ризикових кроків;
- бюджет-слоти й cap частки сильної моделі — узгоджено з `context-engineering.md` (власник `continuation-memory`);
- **маршрутизація без вимірювання якості заборонена** — кожен дешевий крок за валід-гейтом/рубрикою (`validation-mesh`).

Підбір моделі (тут/канон) ≠ failover при падінні провайдера — це `multi-provider-ai-orchestration` (rate-limit/quota/ротація ключів).
