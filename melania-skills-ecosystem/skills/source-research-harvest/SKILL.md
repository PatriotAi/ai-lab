# Source Research Harvest — v0.2.0

## 🛡️ Протокол Збереження Перед Оновленням (ОБОВ'ЯЗКОВО)
Перед БУДЬ-ЯКОЮ зміною цього скіла: 1) ПЕРЕЧИТАТИ живий `SKILL.md`+`references/` з диску;
2) ПОРІВНЯТИ версії (диск новіший → база); 3) ЗВІРИТИ diff; 4) ЗЛИВАТИ не замінювати; 5) snapshot.

## Core Rule
Це **тонкий оркестратор + acquire-front-end**, НЕ копія. Унікальний вміст — лише §1 (Information
Maximization). Стадії 2–7 ДЕЛЕГУЮТЬ наявним скілам. Фінальна валідація — РЕАЛЬНА (`skill_guard.py`
+ `audit_scan.py`), не grep. Запис будь-якого скіла — лише після diff (Закон II).

## Decision Gate — чому окремий скіл
Пайплайн harvest вже існує розподілено (auditor mode B = backlog/execute; rlm-harness = глибина;
validation-mesh = QA; continuation-memory = стан). **Прогалина, яку додає цей скіл:** (а)
**acquire-front-end** — максимізація інфо з мінімального/обмеженого джерела (немає в жодному скілі);
(б) **єдиний тригер** «Давай дослідимо це для оновлення»; (в) **integrate-check** binding. Решта — делегування.

## §1. INFORMATION MAXIMIZATION (acquire-front-end — ГОЛОВНЕ, нове)
**Принцип: НІКОЛИ не зупиняйся на «недоступно». З найменшого входу напрацюй максимум перевіреного.**

### Сходи здобуття (graceful fallback)
1. **Тип джерела** — визнач: URL · зображення · назва/handle · фрагмент тексту · розпливчаста фраза.
2. **Пряме здобуття** — спробуй напряму: fetch URL · «прочитай» зображення (усе видиме: текст, лого, контекст) · resolve назви.
3. **Fallback при блоку/невдачі** (роби по черзі, не здавайся):
   - URL не fetch-иться → **web_search** fetchable-дзеркала/лінку → fetch його.
   - Лише назва/handle/бренд → **search** щоб розкрити в конкретику.
   - Зображення без даних → витягни ВСЕ видиме як seed (OCR/опис) → search по витягнутому.
   - Усе ще закрито → **аналіз ДОМЕНУ/позиціювання** джерела + **валідація реальними поточними даними**
     (приклад: фід каналу закритий → проаналізували призначення з опису → дослідили реальні
     тренди у тому домені → змапили на екосистему).
4. **Чесний Source-Reality** — зафіксуй: що здобуто / чого нема / який проксі-дериватив застосовано.
   **НІКОЛИ не вигадуй джерело чи дані.**
5. **Максимізація** — від seed дай МАКСИМУМ корисного й перевіреного: кілька кутів пошуку,
   крос-валідація, Tier1-джерела + «необроблені діаманти». Мета — виконати задачу повноцінно з мінімуму.

**Правило вартості:** дешеві кроки (search) — щедро; дорогі — економно; внутрішнє опрацювання
найкомпактнішою мовою, фінал — українською (узгоджено з `continuation-memory` / `rlm-harness`).

## §2–7. Пайплайн (ДЕЛЕГУЄ механіку)
2. **RESEARCH (глибина)** → `rlm-harness` (Deep Research рецепт; диригент дорогий, суб-процеси дешеві).
3. **CROSS-ANALYZE + BACKLOG** → `skill-ecosystem-auditor` (harvest mode B + `harvest-report-template`).
   Чесно: більшість трендів зазвичай ВЖЕ покрито — шукай реальні прогалини, не дублюй.
4. **STOP-gate (Закон II)** → беклог read-only до схвалення MA.
5. **APPLY + REAL validation** → на КОЖЕН схвалений пункт: re-read повного вмісту → snapshot → diff →
   apply (merge) → `skill_guard.py --validate` → bump+CHANGELOG → `--snapshot`; підсумок `audit_scan.py`.
   **Правило (з harvest-template):** беклог з ОПИСІВ → re-read скасовує/міняє пункти; не застосовуй наосліп.
6. **INTEGRATE-CHECK** → які НОВІ функції/стратегії використано цього прогону (acquire-fallback, нові
   tools, валідатори)? Чи вони вже кодифіковані у скілах? Ні → `skill-ecosystem-auditor` mode A
   (internal harvest) → пропозиція додати. Гарантує «функції, що юзалися = функції, що інтегровані».
7. **STATE (анти-компресія)** → `continuation-memory`: ДО — план-стан STENO на диск; ПІД ЧАС — snapshot+прогрес
   після кожного скіла; ПІСЛЯ — continuation-package. Довгий прогін не втрачає напрацьоване при стисненні.

## Behavior
| Ситуація | ✓ Дія | ✗ Ніколи |
|----------|-------|----------|
| Джерело «недоступне» (fetch впав) | пройди сходи fallback (search→домен-аналіз→валідація трендами) | не кажи «недоступно» і не зупиняйся |
| Лише назва/зображення як тригер | витягни seed → максимізуй пошуком | не проси більше даних без спроби здобути |
| Знайдені тренди | звір з екосистемою, бери лише реальні прогалини | не дублюй уже покрите |
| Готовий застосувати | re-read повного вмісту ПЕРЕД diff | не патч з опису/контексту наосліп |
| Фінальна перевірка | `skill_guard`+`audit_scan` | не покладайся на grep як фінал |
| Довгий прогін | стан на диск до/під час/після | не тримай напрацьоване лише в контексті |
