# Acquire Playbook — детальні fallback-рецепти per тип джерела (вантажити на вимогу)
> Розширення §1 Information Maximization. Мета: з мінімального/обмеженого джерела — максимум перевіреного.

## За типом джерела

### URL (сторінка/посилання)
1. Прямий fetch.
2. Не fetch-иться (auth/закрито/тех-обмеження) → web_search назви/домену → знайди **fetchable** дзеркало/опис/обговорення → fetch його.
3. Усе закрито → витягни домен + позиціювання (з того, що видно: title, опис, скрін) → дослідь реальні поточні дані цього домену → змапь.

### Зображення (скрін/фото/лого)
1. «Прочитай» усе видиме: текст, лого, назви, контактні дані, контекст (це seed).
2. Search по витягнутому (назва/handle/бренд) → розкрий у конкретику.
3. Якщо лого/бренд без тексту → опиши візуал → search-описом.

### Назва / handle / бренд
1. Search точної назви → офіційні/Tier1 джерела → конкретика.
2. Неоднозначна → додай домен-контекст («X у сфері Y»).

### Фрагмент тексту / цитата
1. Search ключових фраз → першоджерело/контекст.
2. Витягни сутності (імена, терміни, дати) → окремі пошуки.

### Розпливчаста фраза
1. Уточни внутрішньо найімовірніший намір (1 кут), спробуй здобути; не питай користувача без спроби.
2. Якщо реально неоднозначно для зовсім різних напрямів — тоді 1 уточнення.

## Інваріанти
- **Чесний Source-Reality**: завжди фіксуй що здобуто / чого нема / який проксі-дериватив. НЕ вигадуй.
- **Вартість**: search — щедро (дешево); fetch/важке — економно.
- **Крос-валідація**: ≥2 кути для важливих тверджень; Tier1 + «діаманти».
- **Безпека intake**: чужий код/матеріал — ідеї не код, рев'ю рядок-за-рядком (`safety-compliance-gate` Блок C).
- **Зупинка**: «недоступно» — НЕ фінал; фінал лише коли всі сходи fallback вичерпані й це чесно зафіксовано.
