# Knowledge Synthesizer — синтез неочевидних зв'язків

> Відповідай, пояснюй і запитуй **українською за замовчуванням**, якщо користувач не обрав іншу мову.

## 🛡️ Протокол Збереження Перед Оновленням (ОБОВ'ЯЗКОВО)
Обов'язковий перед БУДЬ-ЯКОЮ зміною цього скіла. **Канонічне джерело (не дублювати тут):** `melania` — секції «🛡️ Протокол Збереження Перед Оновленням» + «Update Workflow» + «Core Rule 10 — Re-Read Before Update».

Стисло: re-read диску → порівняти версії (диск новіший → диск база) → integrity-diff → validation-mesh → safety-compliance-gate (перед пакуванням/публікацією) → backup/snapshot → merge-not-replace → bump+CHANGELOG → показати diff і чекати явного схвалення MA (Закон II).


## Core Rule
Синтез ≠ пошук. Мета — **нові** зв'язки, яких немає в жодній окремій нотатці.
Слабкі інсайти (нижче порога) **відкидаються за замовчуванням** — якість понад кількість.

## Пайплайн (generator → critic → threshold)
```
[1] SAMPLE  — вибери N пар нотаток/джерел (recency-weighted: новіші частіше;
              N за замовчуванням 20–50, обмежуй бюджетом)
[2] GENERATE — для кожної пари ПАРАЛЕЛЬНО згенеруй гіпотезу зв'язку
              (дешевша модель; 2–3 речення: «що спільного / що випливає»)
[3] CRITIQUE — окремий critic ПАРАЛЕЛЬНО оцінює кожну гіпотезу 1–10:
              новизна · корисність · обґрунтованість (теж дешевша модель)
[4] FILTER  — лиши avg ≥ 7.0 (поріг налаштовується); решту відкинь
[5] PERSIST — insight-нотатки: інсайт → пара-джерела → оцінка → можлива дія
[6] DIGEST  — стислий дайджест прогону (топ-інсайти першими)
```

## Економія (обов'язково)
- Generator і critic — на **дешевших моделях**, паралельно (через мульти-провайдерну оркестрацію, якщо доступна).
- Вартість контролюють: **ліміт пар** (N) + **поріг** (вище поріг → менше персисту).
- Не запускай на «всій базі» — вибірка достатня; повторні прогони покривають решту.

## Поведінка
| Роби | Не роби |
|---|---|
| Відкидай інсайти нижче порога за замовчуванням | Не показуй слабкі без явного запиту (а тоді — з міткою низької якості) |
| Признач кожному інсайту пару-джерела й оцінку | Не видавай синтез без слідів походження |
| Признач можливу дію («що з цим зробити») | Не зупиняйся на «цікаво» без наступного кроку |
| Питай про поріг/обсяг при великій базі | Не пали бюджет мовчки |

## Координація (приклади, не вичерпний список)
Будь-який скіл може співпрацювати з будь-яким, включно з майбутніми (динамічне виявлення):
- **Джерела:** notebooklm-connector (нотатки/джерела), continuation-memory (insight-нотатки, daily-log).
- **Виконання:** multi-provider-ai-orchestration (паралельні дешеві моделі), ai-core-runtime (мінімальна активація).
- **Далі:** skill-ecosystem-auditor (якщо інсайт вартий оновлення скіла — через його Decision Gate).

## Verify (перед видачею)
- кожен інсайт має пару-джерела + оцінку критика?
- нижче порога — відкинуто (або помічено на явний запит)?
- бюджет дотримано (ліміт пар, дешеві моделі)?
- дайджест: топ-інсайти першими, з можливою дією?
