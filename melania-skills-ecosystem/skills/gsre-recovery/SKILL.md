# GSRE — Global Skill Recovery & Enrichment
> Пояснення — українською за замовчуванням (українською-перша); назви інструментів та ідентифікатори лишаються англійською.

## 🛡️ Протокол Збереження Перед Оновленням
Перед БУДЬ-ЯКОЮ зміною цього скіла — канон у `melania` (секції «Протокол Збереження» + «Update Workflow» + Core Rule 10). Стисло: re-read → diff → validate → safety-gate → backup → merge-not-replace → bump+CHANGELOG → показати diff і чекати схвалення MA.

## ⚠️ Чесні межі — ОГОЛОСИТИ ПЕРЕД ПОШУКОМ (обов'язково)
Цей скіл МУСИТЬ озвучити реальні можливості до запуску й **ніколи не вдавати ширший доступ**. Якщо чогось не вмію — кажу прямо «не можу», а не «зроблю».

**МОЖУ:**
- Шукати в минулих чатах через `conversation_search` / `recent_chats` — АЛЕ лише в МЕЖАХ поточного скоупу: якщо ми в проекті — тільки чати ЦЬОГО проекту; якщо поза проектом — тільки поза-проектні чати.
- Читати вміст і номери версій з ДОСЯЖНИХ чатів.
- Зчитувати диск (`/mnt/skills`), `outputs/`, робочі теки; порівнювати з поточним станом.

**НЕ МОЖУ:**
- Шукати одночасно по ВСІХ проектах і чатах з одного місця — інструмент скоупиться.
- Доступитись до чатів ПОЗА поточним скоупом (інші проекти / інші поза-проектні сесії звідси невидимі).
- Завантажувати чи встановлювати скіли в бібліотеку замість користувача — лише віддаю файли.

→ **Для повного покриття:** запустити GSRE З КОЖНОГО проекту + з поза-проектного простору окремо (один чат не бачить усе).

## 🔎 Opt-in пре-опитування (перед запуском)
ЗАВЖДИ перед пошуком: оголосити скоуп + спитати згоду + уточнити ціль. Шаблон:
> «Я можу пошукати в **[поточний скоуп]** (бачу N досяжних чатів). Інші проекти/чати звідси недосяжні.
> Що шукаємо? — (а) усе, що могло загубитися; (б) конкретна тема **X**; (в) напрацювання для скіла **Y**.
> Запускати в доступному скоупі? [так / уточнити]»

Не запускати важкий пошук без явного «так». Якщо користувач одразу дав ціль і згоду — діяти.

## Фази GSRE (після згоди)
0. **Scope check** — визначити й оголосити, що реально досяжно (проект? скільки чатів?).
1. **Inventory** — інвентаризувати наявне: диск (`/mnt/skills/user`), `outputs/`, working-теки, поточна пам'ять.
2. **Forensic search** — `conversation_search` за темами (ключові слова контенту, не «обговорювали»), `recent_chats` за часом; кілька запитів різними формулюваннями.
3. **Cross-reference** — порівняти знайдене з поточним станом; виявити: втрачене (claimed-але-відсутнє), застаріле, неінтегроване.
4. **Backlog** — список знахідок з дією (recover / reconstruct / integrate) + severity; подати MA, чекати схвалення.
5. **Integrate** — лише схвалене, адитивно, під Pre-save gate; перед видачею — `pre-delivery-gate`.

## Принципи відновлення
- Forensic recovery > видалення неверифікованого (спершу шукати, не стирати).
- Дослівне відновлення, де можливо; реконструкція — позначати як таку.
- Структурна першопричина історичних втрат evals: пакувальник виключає `evals/` з `.skill` → тримати source-копії окремо.

## Координація
ВИКЛИКАЄ за потреби: `continuation-memory` (стиснення/відновлення стану), `validation-mesh` (валідація відновленого), `pre-delivery-gate` (перед видачею), `melania` (інтеграція через Pre-save gate). Намір-роутинг — через `semantic-router`.
