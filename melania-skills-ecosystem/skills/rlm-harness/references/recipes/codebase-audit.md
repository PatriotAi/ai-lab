# Recipe: Codebase Audit

Аудит великої кодової бази: архітектура, якість, тех-борг, ризики → пріоритезовані рекомендації. (Не суто безпековий — це `security-audit`.)

## 1. Тригери
- ALWAYS: огляд великого репо/моноліту на якість/архітектуру/борг, «проаудит код», «де тех-борг і ризики».
- DO NOT: пошук вразливостей (→ `security-audit`); правка одного файлу (→ `surgical-code-refactoring` напряму).

## 2. Objective contract
- **Вхід:** репо/каталог + (опц.) фокус (архітектура / якість / борг / продуктивність).
- **Вихід:** пріоритезовані знахідки (severity × зусилля) + рекомендації.
- **Готово:** модулі систематично пройдені; кожна знахідка з доказом у коді й пріоритетом.

## 3. Control loop
- **REPLAN коли:** виявлено непокритий модуль/шар; знахідка потребує крос-модульного аналізу залежностей.
- **Збіжність:** карта модулів пройдена + знахідки пріоритезовані.
- **Гарди:** max глибина/файли/ходи; рубрика пріоритезації.

## 4. Topology
Hierarchical: planner будує карту модулів → паралельні воркери-аналізатори по модулю (long-context) → architecture-judge → synth.

## 5. Per-step model class
| Крок | Клас |
|---|---|
| Карта модулів / декомпозиція | топовий reasoning |
| Читання/аналіз по модулю (паралельно) | дешевий long-context |
| Architecture / coupling judge | сильний |
| Синтез + пріоритезація | сильний |
| Запропоновані правки | сильний + `surgical-code-refactoring` (patch, не rewrite) |

## 6. Validation gates (`validation-mesh`)
Знахідки звірені з реальним кодом (немає галюцинованих проблем); пріоритезація за рубрикою (вплив×зусилля); рекомендації не ламають робоче.

## 7. Output contract
Звіт: знахідка · доказ (файл/рядок) · severity · зусилля · рекомендація; топ-пріоритети. Зміни — хірургічно (patch), не масовий rewrite.

## 8. Safety / governance (`safety-compliance-gate`)
Чужий код = недовірений вхід. Правки великого файлу — через `surgical-code-refactoring` (валідація ПЕРЕД інтеграцією, regression-check, не ламати робоче).

## 9. Cost note
Дешеве паралельне читання домінує; сильна модель на architecture-judge/синтезі/правках. Cap частки сильної.

## 10. Evals hook
Baseline провалює: несистемне покриття модулів, галюциновані проблеми без доказу, відсутня пріоритезація.
