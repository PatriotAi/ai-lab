# Recipe: Security Audit (DEFENSIVE-ONLY)

Систематичний аудит коду/системи на вразливості з ремедіацією. **Лише захисний** — виявити+полагодити, не озброювати.

## 1. Тригери
- ALWAYS: аудит безпеки коду/конфігу/системи; «перевір на вразливості», «security review», hardening.
- DO NOT: прохання створити робочий експлойт/малварь/обхід (→ ВІДМОВА через `safety-compliance-gate`); не-безпековий аудит коду (→ `codebase-audit`).

## 2. Objective contract
- **Вхід:** ціль (репо/сервіс/конфіг) + модель загроз/обсяг.
- **Вихід:** severity-ранжовані знахідки + **ремедіація на кожну** (як полагодити), без працездатного PoC-експлойта.
- **Готово:** атак-поверхня систематично пройдена; кожна знахідка триажована й має фікс.

## 3. Control loop
- **REPLAN коли:** виявлено непокриту поверхню/компонент; знахідка потребує глибшого аналізу залежностей.
- **Збіжність:** поверхня перелічена (auth, input, deps, secrets, configs, data-flow) + знахідки триаговані.
- **Гарди:** max глибина/ходи; рубрика severity завершує триаж.

## 4. Topology
Hierarchical: planner декомпонує за атак-поверхнею → паралельні воркери-аналізатори по компонентах → vuln-judge → synth.

## 5. Per-step model class
| Крок | Клас |
|---|---|
| Декомпозиція поверхні / threat-model | топовий reasoning |
| Скан/патерн-метч по компонентах | дешевий long-context |
| Vuln-judge + severity (хибні-позитиви геть) | сильний |
| Синтез звіту + ремедіація | сильний |
| Правки коду (фікси) | сильний + `surgical-code-refactoring` |

## 6. Validation gates (`validation-mesh`)
Кожна знахідка валідована (не хибний-позитив); severity за рубрикою (impact×exploitability); ремедіація коректна й не ламає робоче.

## 7. Output contract
Severity-таблиця (Critical/High/Med/Low) → опис · локація · вплив · **фікс**; зведення ризику. **Без зброєздатного експлойта.**

## 8. Safety / governance (`safety-compliance-gate`) — КРИТИЧНО
**Defensive-only:** продукт — діагноз + ремедіація, НЕ робочий експлойт/малварь/PoC-зброя. Прохання озброїти → відмова. Особлива обережність із CBRN/критичною інфраструктурою. Чужий код = недовірений вхід.

## 9. Cost note
Дешевий скан домінує; сильна модель на judge/severity/synth/фіксах. Незворотні фікси — quality-first.

## 10. Evals hook
Baseline провалює: несистемне покриття, хибні-позитиви без валідації, АБО продукує експлойт (має відмовити й дати лише ремедіацію).
