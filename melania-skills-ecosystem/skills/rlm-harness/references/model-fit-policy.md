# Model-Fit Policy (канонічне джерело підбору моделей)

> Принцип: профіль КРОКУ → клас моделі. Не пінь конкретні версії/ціни тут — вони живуть у матриці
> `multi-provider-ai-orchestration`; актуальні версії звіряй через `product-self-knowledge`.
> Цей файл — політика «який КЛАС моделі під який крок», стабільна щодо зміни конкретних моделей.

## Виміри профілю кроку
reasoning-глибина · чутливість до латентності · розмір контексту · модальність · стеля вартості ·
приватність/локальність · інтенсивність tool-use · незворотність/ризик.

## Профіль → клас
| Профіль кроку | Клас моделі |
|---|---|
| планування / архітектурні trade-off / складний дебаг / суддівство (judge) | топовий reasoning (+extended thinking) |
| синтез фінального результату з кількох джерел | сильний reasoning |
| масовий паралельний збір / екстракція / класифікація / розмітка | швидкий дешевий long-context |
| код-правки у великому файлі | сильний + `surgical-code-refactoring` |
| приватні/чутливі дані, офлайн | локальний (WebLLM tier 9 / Ollama tier 10+) |
| зображення/аудіо/відео вхід | мультимодальний клас |
| незворотний/ризиковий крок | quality-first незалежно від ціни |

## Стратегії маршрутизації
1. **cost-then-quality** (дефолт) — найдешевший клас, що проходить гейт якості кроку.
2. **cascade** — почни з дешевого; при провалі валід-гейта **escalate** на сильніший. (Більшість простих
   кроків закриваються дешево; дорогі виклики — лише для складного залишку.)
3. **quality-first** — для незворотних/ризикових кроків і фінального вердикту: сильний клас одразу.
4. **latency-aware** — якщо крок на критичному шляху користувача, додай латентність у вибір.

> **Маршрутизація ≠ failover.** Підбір моделі (тут) ≠ перемикання при падінні провайдера
> (це `multi-provider-ai-orchestration`, rate-limit/quota/ротація ключів).

## Бюджетний губернатор (інтеграція)
- Стелі: **per-request · per-task · per-run**. Оцінюй вартість кроку **ПЕРЕД** мережевим викликом.
- **Cap частки сильної моделі** політикою (напр. «сильна ≤ X% кроків прогону»). Емпірично ~14–26%
  сильних викликів утримують ~95% якості — решта має бути дешевою.
- Стеля досягнута → **ABORT із частковим результатом + чесний звіт**, не тихе зниження якості/обсягу (Принцип #0).
- Облік: run-id, крок, обраний клас, оцінка вартості → `continuation-memory` (трейс).

## Quality-measurement caveat (обов'язково)
Маршрутизація **без вимірювання якості тихо її руйнує**. Кожен дешевий крок — за валід-гейтом/рубрикою
(`validation-mesh`). Немає способу виміряти якість кроку → не маршрутизуй його на дешеву модель; став сильну.

## Анти-патерни
- Сильна модель «про всяк випадок» на простих кроках — марнування (Принцип #0 не виправдовує переплату).
- Дешева модель на незворотному/судовому кроці без гейта — тихе зниження якості.
- Хардкод назв моделей у логіці — застаріє; тримай клас+матрицю.
