# RLM Harness — Spec (джерело evals)

## Мета
CORE-скіл найвищого рівня: виконувати складні/багатокрокові завдання на найвищому рівні
можливостей — **найсильніша модель-диригент (RLM) керує**, суб-агенти/суб-процеси йдуть на
**найдешевших придатних** моделях; динамічний самокоригований цикл; бюджет на користь якості;
повторювані рецепти важких процесів. Скіл **зв'язує** наявні CORE-скіли, не переписує їх.

## Тригери
- ALWAYS use when: складне/багатокрокове завдання, що потребує оркестрації кількох агентів/процесів;
  динамічного перепланування; підбору моделі під роль/процес; запуску важкого процесу
  (deep research, security audit, конкурентний аналіз, red-team, аудит коду, бенчмаркінг).
- DO NOT use for: просте Q&A в один крок / один виклик однієї моделі (→ конкретний скіл напряму);
  суто рантайм-маршрутизація провайдерів у застосунку (→ `multi-provider-ai-orchestration`);
  механіка топологій (→ `workflow-orchestration`); намір→скіл (→ `semantic-router`).

## Критерії приймання (кожен → eval-кейс)
1. Диригент-роль виконується на найсильнішій reasoning-моделі; воркери/прості кроки — на найдешевших придатних. НЕ все на одній (сильній) моделі.
2. План-перший (повний початковий план, що уточнюється з новими доказами), НЕ міопічний «лише наступний крок».
3. Валід-гейт перед прийняттям результату; маршрутизація без вимірювання якості заборонена.
4. Виявлено прогалину/провал гейта → **таргетоване перепланування** (не «проштовхування» з недостатнім планом).
5. Бюджетний губернатор: стелі (per-request / per-task / run), перевірка ПЕРЕД викликом; cap частки сильної моделі; при стелі — ABORT із частковим результатом + звіт. **Ніколи** не ріже обсяг/якість результату заради токенів (Принцип #0 — економія на процесі, не на результаті).
6. Важкий процес → рецепт вантажиться **на вимогу** (progressive disclosure), не вся бібліотека; застосовує цикл+моделі-на-крок+гейти+контракт виходу рецепта.
7. Security Audit — **defensive-only**: виявити+полагодити, через `safety-compliance-gate`; НЕ продукувати робочий експлойт/малварь.
8. Делегує механіку (топологія→`workflow-orchestration`, роутинг→`semantic-router`, валідація→`validation-mesh`, стан→`continuation-memory`, провайдер-рантайм→`multi-provider-ai-orchestration`), НЕ переписує.
