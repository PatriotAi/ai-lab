# Content Processors для NotebookLM

## Алгоритми обробки за типом контенту

---

## Веб-сторінки

```
1. web_fetch(url)
2. Витягти: <title>, <meta description>, <h1-h6>, основний текст
3. Видалити: навігацію, рекламу, footer, boilerplate
4. Перевірити: мова, дата публікації, автор
5. Структурувати: заголовок → підзаголовки → параграфи
6. Обмежити до 100,000 символів якщо дуже довга
```

**Вихідний формат:**
```markdown
# [Заголовок сторінки]
**Джерело:** [URL]
**Автор:** [якщо є]
**Дата:** [якщо є]

[Структурований контент]
```

---

## Наукові статті / Академічний контент

```
1. Витягти Abstract / Резюме
2. Структура: Вступ → Методологія → Результати → Висновки
3. Зберегти всі цифри, статистику, посилання
4. Зберегти список літератури (корисно для NotebookLM)
5. Виділити ключові терміни
```

**Автотригер**: Study Guide + FAQ

---

## Новини та репортажі

```
1. Витягти: хто, що, коли, де, чому, як
2. Виділити прямі цитати
3. Позначити суб'єктивні оцінки vs факти
4. Додати контекст якщо відомий
```

**Автотригер**: Briefing Doc + Timeline (якщо серія подій)

---

## YouTube відео

```
1. Перевірити наявність транскрипту
2. Якщо є → додати URL напряму в NotebookLM
3. Якщо ні → запропонувати альтернативи:
   - Знайти статтю по темі відео
   - Скористатись youtube-transcript сервісом
   - Переглянути і законспектувати вручну
4. Додати метадані: назва, канал, дата, тривалість, теги
```

---

## GitHub репозиторії

```
1. web_fetch README.md
2. Додати структуру репо (дерево файлів з опису)
3. Включити: мета, технологічний стек, основні концепції
4. Для документації: зібрати /docs/ сторінки окремими джерелами
5. Для коду: не додавати raw код, лише коментарі та пояснення
```

---

## Google Docs / Slides

```
1. Перевірити sharing (потрібен "Anyone with link")
2. Для Docs: пряме посилання в NotebookLM
3. Для Slides: пряме посилання в NotebookLM
4. Попередити користувача про необхідність публічного доступу
5. Зазначити: оновлення документу = автооновлення в NotebookLM
```

## Пакетна обробка кількох URL

```
Стратегія для 3+ URL:

ФАЗА 1 — Паралельна обробка (до 5 URL одночасно):
  → web_fetch кожного URL
  → Визначити тип та якість контенту
  → Оцінити релевантність один до одного

ФАЗА 2 — Пріоритизація:
  → Первинні джерела > Вторинні
  → Нові > Старі (якщо тема актуальна)
  → Повні тексти > Короткі огляди

ФАЗА 3 — Побудова структури:
  → Визначити центральну тему
  → Виявити підтеми
  → Побудувати Index Document

ФАЗА 4 — Рекомендації:
  → Послідовність додавання (від загального до конкретного)
  → Які функції NotebookLM запустити і в якому порядку
```

## Виявлення та усунення дублікатів

```
Перевірки перед додаванням:
□ Чи є вже подібний URL в Notebook?
□ Чи є перетин контенту >80%?
□ Чи є новіша версія цього матеріалу?

Якщо дублікат знайдено:
→ Повідомити користувача
→ Порівняти версії
→ Запропонувати: замінити / залишити обидва / пропустити
```

## Багатомовна обробка

```
Якщо джерела різними мовами:
1. Визначити основну мову Notebook (мова більшості джерел)
2. Підготувати резюме іншомовних джерел основною мовою
3. Зберегти оригінальний текст як додаток
4. Позначити мову в метаданих

NotebookLM підтримує крос-мовний аналіз але:
- Audio Overview буде мовою інтерфейсу Google
- Chat відповідає мовою запиту
```
