# Власний маркетплейс плагінів · `patriotai-lab`

Каталог плагінів (plugin marketplace) для Claude Code, який роздає навички лабораторії
як встановлювані бандли. Живе просто в цьому репозиторії: файл каталогу —
`.claude-plugin/marketplace.json`, самі плагіни — `plugins/<назва>/`.

**Навіщо.** Досі навички були доступні лише всередині `ai-lab` (симлінки в `.claude/skills/`).
Маркетплейс робить їх встановлюваними **ззовні** — у будь-якому іншому проєкті, однією
командою, з версіями й оновленнями.

---

## Як підключити (для споживача)

```bash
# 1. додати маркетплейс
claude plugin marketplace add PatriotAi/ai-lab

# 2. встановити потрібний бандл
claude plugin install melania-governance@patriotai-lab

# 3. подивитися, що всередині, і скільки це коштує токенів
claude plugin details melania-governance
```

Оновлення каталогу — `claude plugin marketplace update patriotai-lab`.
Усе те саме працює й слеш-командами всередині сесії: `/plugin marketplace add …`.

Для тесту без GitHub — з локальної теки: `claude plugin marketplace add ./ai-lab`.

## Як це влаштовано

```
.claude-plugin/marketplace.json     ← каталог: 6 записів, source = ./plugins/<назва>
plugins/<назва>/
├── .claude-plugin/plugin.json      ← маніфест бандла (name, version, keywords…)
└── skills/<скіл> → симлінк         ← на melania-skills-ecosystem/ або .claude/skills/
```

**Чому симлінки, а не копії.** Єдине джерело правди лишається там, де його веде
governance: `melania-skills-ecosystem/skills/` (під `maintain.py verify`) і
`.claude/skills/` (лабораторні). Бандл не дублює вміст — він лише вказує, що входить.
Оновив скіл в одному місці — оновилися всі бандли, які його віддають.

**Чому це працює при встановленні.** Claude Code копіює плагіни в локальний кеш
(`~/.claude/plugins/cache`), і симлінк, ціль якого лежить **усередині маркетплейсу**,
при копіюванні **розіменовується** — у кеш їде реальний вміст. Симлінк, що веде **за межі**
маркетплейсу, мовчки пропускається (захист від затягування довільних файлів хоста) —
саме тому гейт окремо перевіряє, що жодна ціль не виходить за корінь репозиторію.

Перевірено обома шляхами встановлення — з локальної теки і з git-клону гілки: у кеші
опинилися **35 `SKILL.md` і жодного симлінка**, разом із `references/`, 28 `evals.json`
і 28 guard-скриптами; `diff -rq` джерела й кеш-копії (`rlm-harness`, `semantic-router`)
не показав різниці.

## Місток: споживання з іншого репозиторію

Перший споживач каталогу — [`PatriotAi/PatriotAiWIKI`](https://github.com/PatriotAi/PatriotAiWIKI).
Навички туди **не копіюються**: увесь місток — це `.claude/settings.json` у тому репозиторії,
який оголошує маркетплейс і вмикає бандли:

```json
{
  "extraKnownMarketplaces": {
    "patriotai-lab": {
      "source": { "source": "github", "repo": "PatriotAi/ai-lab" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": { "melania-governance@patriotai-lab": true }
}
```

Оскільки бандли описані відносними шляхами, Claude Code бере їх із тієї ж копії
маркетплейсу — окремий `claude plugin install` споживачеві не потрібен. Перевірено ділом:
свіжа `-p`-сесія в теці, де немає нічого, крім цього файла, сама поставила й завантажила
всі шість бандлів (подія `init` перелічила їх із шляхами в кеші).

Умови, за яких місток мовчить: тека не позначена довіреною, немає доступу до приватного
`ai-lab`, або каталог ще не в гілці за замовчуванням. Ціна вмикання всіх шести — **близько
12 000 токенів always-on** на сесію (виміряно `claude plugin details`).

**Свідомо не зроблено:** маркетплейс **не** прописаний у `.claude/settings.json` самого
`ai-lab`. Інакше тутешні сесії вантажили б ті самі скіли двічі — раз через `.claude/skills/`,
раз через плагіни. Каталог призначений для споживання **ззовні**.

## Гейти

```bash
python3 scripts/verify-marketplace.py            # звичайний гейт (exit 0/1)
python3 scripts/verify-marketplace.py --publish  # + claude CLI обов'язковий (без нього — помилка)
python3 tests/marketplace-gate-canary.py         # канарки: чи ловить гейт поломки
```

`verify-marketplace.py` перевіряє: резолв кожного симлінка · межі маркетплейсу ·
покриття (жодного скіла-сироти, жодного дубля) · **що скіл у бандлі — саме симлінк**, а не
копія каталогу (копія тихо ламає «єдине джерело правди»: зміни в справжньому скілі перестають
доходити до бандла) · збіг версій каталог ↔ `plugin.json` · похідні лічильники в описах ·
зарезервовані імена маркетплейсів · політику MIT · і прогонить офіційний
`claude plugin validate --strict` по каталогу та кожному плагіну.

Схемна валідація потребує `claude` CLI. **Без нього** звичайний прогін лише попереджає
(так працює CI, де CLI немає — раннер тестів показує це як «не ганялось», а не як зелене),
а `--publish` **падає**: реліз без схемної перевірки міг би випустити зламаний маніфест.

`marketplace-gate-canary.py` ламає копію репозиторію 16 різними способами й вимагає, щоб
гейт впав саме на цьому — плюс два контролі: чиста копія проходить, а без `claude` і без
`--publish` гейт лише попереджає. Перелік інцидентів, які набір обіцяє закрити, виписаний
у шапці файлу; додаєш перевірку — додавай туди сценарій. Сценарій зі схемною помилкою
потребує `claude` CLI: без нього він чесно позначається «не ганявся», а не зараховується.

## Ліцензія — MIT скрізь

Рішенням власника від 2026-09-28 уся екосистема під **MIT**, однаково на кожному рівні:
`LICENSE` репозиторію, `melania-skills-ecosystem/LICENSE.txt`, поле `license:` у frontmatter
усіх 28 SKILL.md екосистеми **і 7 лабораторних навичок** (`.claude/skills/`, а також у
`templates/skill.md`, щоб нові не поверталися до дефекту), `license` у кожному
`plugin.json` і в кожному записі каталогу. Рішення скасовує
попереднє на користь Apache-2.0 — контекст у [`PLAN.md`](PLAN.md).

До цього поле `license:` мало чотири різні значення (`Proprietary` ×15, `MIT` ×8,
`Apache-2.0` ×4, одне невизначене) при Apache-2.0 у `LICENSE` — розбіжність, яку виявив
гейт маркетплейсу. Тепер однорідність **машинна**: `verify-marketplace.py` падає, щойно
десь з'явиться не-MIT, тож наступний скіл не зможе тихо принести іншу ліцензію.

Уточнення після рев'ю: перша версія гейта приймала **відсутнє** поле `license:` — і саме
тому пропустила 7 лабораторних навичок, які його не мали (легкий frontmatter лише з
`name` і `description`). Тепер відсутнє поле — порушення, а читається саме frontmatter:
рядок «license: MIT» у тілі (приклад, цитата) метаданими скіла не вважається.

Публічність каталогу — окреме рішення власника, воно не ухвалене
(`CLAUDE.md` → «Коли ЗУПИНИТИСЯ і спитати власника»).

## Як додати новий плагін або скіл

1. Скіл у бандл: `ln -s ../../../<шлях-до-скіла> plugins/<бандл>/skills/<назва>`.
2. Новий бандл: тека `plugins/<назва>/` з `.claude-plugin/plugin.json` + `skills/`,
   і запис у `.claude-plugin/marketplace.json` (`source: "./plugins/<назва>"`).
3. Оновити лічильники в описі запису та в таблиці вище.
4. `python3 scripts/verify-marketplace.py` → exit 0. Інакше — гейт скаже, що саме розійшлося.
