# Глосарій / Glossary (UA ⇄ EN)

Єдина термінологія для багатомовної консистентності. Доповнюй у міру роботи.

| Українською | English | Нотатка |
|-------------|---------|---------|
| навичка | skill | автоматизація-інструкція для Claude Code |
| хук | hook | скрипт на подію (SessionStart, Stop тощо) |
| експеримент | experiment | одиниця роботи з гіпотезою і висновком |
| дорожня карта | roadmap | беклог напрямків |
| журнал висновків | learnings log | компаундна пам'ять |
| наскрізний зріз | vertical slice | мінімальний наскрізний робочий шматок |
| субагент | subagent | окремий агент під підзадачу |
| пайплайн | pipeline | ланцюжок кроків автоматизації |
| GMI (Загальна Модель Інтелекту) | General Model of Intelligence | інваріантний кістяк рамок інтелекту (не одна теорія) |
| інваріант (інтелекту) | invariant | повторюваний функціональний режим-течія (G1–G7) |
| вісь спостерігача | observer axis | патерн «невизначене → (read-out) → визначене» на 3 рівнях |
| детермінація / зчитування | determination / read-out | коміт розподілу-гіпотез у визначений результат (G7) |
| модель світу | world-model | внутрішня передбачувальна модель середовища |
| когнітивна архітектура | cognitive architecture | інженерна схема мислення (SOAR, ACT-R, Common Model) |
| стек ефективності | efficiency stack | набір принципів ощадності мозку (P1–P7) |
| декларативний гейт | declarative gate | Перевірка, яку навичка САМА заявляє у `gates.json` поруч із `SKILL.md` (схема v1: `id` · `point` · `command` · `blocking` · `onError` · `timeout` · `why`); виконавець — `scripts/run-gates.py`. Точки: `verify`, `delivery`. Двокроковий контракт: спершу «чи відпрацювала сама перевірка» (→ `onError`), потім «знахідка чи ні» (→ `blocking`). `command` — список, не рядок; виконавець лише `python3`/`bash`; шлях усередині репо. `gates.json` входить у підпис виконуваної поверхні. Рішення власника 2026-09-30; канон — `docs/gates.md` |
| виконувана поверхня навички | executable surface | Усе, що навичка МОЖЕ виконати: `allowed-tools` (які інструменти їй дозволено), `hooks` (блок у frontmatter) і файли `scripts/` і `gates.json`. Записана в `melania-skills-ecosystem/SURFACE.json`; **розширення** (нова навичка · додані права · доданий чи змінений скрипт · знята заява `allowed-tools`) без записаної згоди `skill-surface` (ціль = назва навички) — помилка `scripts/check-skill-surface.py`; звуження — лише інформація. Навіщо окремо від хеша `SKILL.md`: `resync` перебирає новий хеш як норму, тож розширення прав проходило `resync` → `verify` мовчки (виміряно 2026-09-30) |
| дзеркальна лінза (дзеркальний режим) | mirror lens | Друга лінза оцінки входу: які його тези/властивості ми **самі не використовуємо** (доказ — диск та історія git, не пам'ять). Перша — «що імпортувати». «Нема що імпортувати» ≠ «нема цінності». Канон — `source-research-harvest` §1½, `CLAUDE.md` §6 (з 2026-10-09) |
| радар розходження | drift radar | `scripts/check-main-drift.py`: що main зробив у файлах гілки (прогноз конфліктів — `git merge-tree`, без змін у робочій теці), незлиті гілки з тими самими файлами, карта паралельної роботи. Щостарту сесії друкує лише знахідки. Смислового дубля в РІЗНИХ файлах не бачить |
| union-журнал | union journal | Журнал записів, для якого `.gitattributes` вмикає вбудований `merge=union`: злиття зберігає обидві сторони замість конфлікту. Ціна — тихий дубль старого рядка, зміненого обома гілками; запобіжник — `scripts/check-union-journal.py`. Лише для журналів дописування (`docs/learnings.md`); **не** для `security/consent.md` (воскресив би відкликану згоду) |
| розбите вікно | broken window | відомий борг у реєстрі `docs/WINDOWS.md`: заглушка, TODO, пропущена перевірка, іменна межа покриття, незакрите рішення. Стани: `open` (борг є) · `fixed` (закрито, рядок лишається як історія) · `waived` (свідомо не закриваємо — **з причиною й датою**, бо це рішення, а не забудькуватість). Лічильник відкритих рахує скрипт, не людина. Режим за замовчуванням — облік; `--strict` блокує. Гейт перед видачею (`pre-delivery-gate` п.10) називає відкриті вікна у здачі |
| незворотність рішення | decision reversibility | рейтинг **`reversible`** (відкат локальний і дешевий) / **`costly`** (відкат чіпає багато місць — позначаємо, не блокуємо) / **`one-way`** (відкат = міграція або зламаний контракт → **рішення власника ДО реалізації**). Оцінюється РІШЕННЯ, не складність задачі, і на етапі дизайну — бо гейт дій цього не бачить: запис рішення у файл є звичайним `R1`. Правило проти інфляції: сумніваєшся — `reversible`. Канон — `docs/methodology.md`, перевіряє `scripts/check-reversibility.py` |
| ціль записаної згоди | consent target | Синтаксис `правило@ціль` у першій клітинці `security/consent.md` (F-17): для злиття PR через MCP — ціль `owner/repo#N`, для виконуваної поверхні навички — `skill-surface@<назва навички>`. Збіг **точний** (регістр не важить); рядок без цілі дію з відомою ціллю **не відкриває**, рядок із ціллю не відкриває дію без цілі. Раніше згода ключувалась лише на інструмент, і «згода на PR #45» відкривала злиття будь-якого PR до кінця строку |
| рівень доказовості | evidence level | тег **[E]** перевірено ділом (з вказівником, який **існує на диску** — формат вказівника ще не доказ) / **[C]** обґрунтоване, машинно не перевірене / **[S]** гіпотеза / **[?]** правильна відповідь **не виводиться з наявної специфікації** (з 2026-09-27: ставиться за фактом «тест до [E] не будується», мусить назвати «бракує: …», не падає гейтом, і відхиляється, якщо доказ насправді існує — guard проти над-абстенції). Обов'язковий для фактичних тверджень у скілах (секція `Critical Facts`, обов'язкова в кожному скілі) і докам — melania Core Rule 14, гейт `maintain.py verify`. Директиви не тегуються: правило не буває істинним чи хибним |
