# Дорожня карта лабораторії / Roadmap

Жива відповідь на 6 базових питань. Оновлюємо в міру руху.
Пріоритети: **P0** — фундамент/зараз · **P1** — далі · **P2** — згодом.

---

## 1. Додаткові автоматизації, які варто реалізувати
- **P0** `SessionStart`-хук — щосесії підвантажує контекст лабораторії (конвенції,
  глосарій, статус експериментів). Навичка `session-start-hook` вже доступна.
- **P0** Skill-фабрика (`skill-new`) — шаблонне створення нових навичок за хвилини.
- **P1** Двомовний контент-пайплайн: дослідження (`deep-research`) → чернетка →
  переклад UA/EN з єдиним глосарієм → публікація.
- **P1** GitHub-автоматизація: розбивка issue → задачі, авто-changelog, тріаж PR.
- **P1** Публікація-конвеєр: текст → Canva-картка (Canva MCP) → деплой на Vercel (Vercel MCP).
- **P2** Захоплення ідей (`idea-capture`) — швидкий запис у беклог `experiments/`.
- **P2** Регулярні задачі через `/loop` або `send_later` (напр. щотижневий огляд).

## 2. Реорганізація наявних автоматизацій
- Зараз автоматизації — це платформні хуки в `~/.claude` (поза версіонуванням репо).
- **P0** Перенести користувацькі автоматизації в репозиторій (`.claude/`, `skills/`,
  `automations/`) — щоб були відтворювані, під рев'ю, портативні.
- **P0** Розшарувати: **глобальне** (`~/.claude`, крос-проєктне) vs **проєктне** (`.claude` у репо).
- **P1** Стандарт: кожна навичка самодостатня (SKILL.md + чіткий опис-тригер). Одна відповідальність.
- **P1** Єдине джерело правди — `CLAUDE.md` (✅ додано).

## 3. Що оптимізувати в проєктах
- **P0** `CLAUDE.md` (пам'ять проєкту) — найбільший виграш: сесії не перевідкривають контекст. (✅)
- **P0** Таксономія тек + конвенції імен. (✅ структуру закладено)
- **P1** Глосарій/термінбаза для багатомовної консистентності → `docs/glossary.md`.
- **P1** Шаблони для повторюваних артефактів (експеримент, навичка, документ). (✅ старт)
- **P1** Allowlist дозволів у `settings.json` — менше підтверджень (є навичка `/fewer-permission-prompts`).
- **P2** Відтворювані експерименти: кожен = тека з README/входами/виходами/висновком.

## 4. Зміни в методології / нові навички
- **P0** Експеримент-орієнтований метод: гіпотеза → запуск → вимір → лиши/прибери → висновок.
  (✅ `docs/methodology.md`)
- Нові навички-кандидати:
  - `skill-new` — створення навичок (P0)
  - `translate-uaen` — двомовна локалізація з глосарієм (P1)
  - `experiment` — старт/трекінг експерименту (P1)
  - `weekly-review` — ретроспектива (P2)
  - `publish` — дослідження → документ → Canva → Vercel (P2)
- Унікальні фічі: журнал висновків (`docs/learnings.md`), що компаундиться;
  двомовність за замовчуванням; метрики продуктивності.

## 5. Що спростити / безпека
Репозиторій майже порожній — спрощувати поки нічого, але ставимо **запобіжники зараз**:
- **P0** `.gitignore` — щоб не комітити сміття (node_modules, .env, артефакти, OS-файли). (✅)
- **P0** Жодних секретів у репо: токени Canva/Vercel/GitHub — лише env. Додати `SECURITY.md` з правилами.
- **P1** Мінімальні скоупи MCP; перевірити мережеву політику (Claude Code on the web).
- **P1** Правило проти шуму: «одна автоматизація — одна задача», без дубльованих хуків/навичок.
- Платформні хуки (`stop-hook-*`, `session-start-git-identity`) — інфраструктура, лишаємо.

> **✅ Зроблено (червень 2026):** довершено план із Copilot-сесії — CI безпеки
> (gitleaks, Trivy, Semgrep), `pre-commit`, Dependabot, CODEOWNERS, `.env.example`,
> `CONTRIBUTING.md`, шаблони Issue/PR, `projects/` + `project-template/`, `scripts/`, `security/`.
> Лишилось (поза файлами): увімкнути branch protection у налаштуваннях репозиторію.

## 6. Додаткові рекомендації
- Почати з одного **наскрізного зрізу** — довести одну автоматизацію до кінця, перш ніж розширювати.
- Лабораторія самодокументована (CLAUDE.md + журнал висновків).
- Двомовність за замовчуванням.
- Використати під'єднані MCP (Canva/Vercel/GitHub) як «руки» лабораторії.
- Регулярний ритм: щотижневий огляд через `/loop` або `send_later`.
- Промпти/навички — як код: версіонуй, рев'юй, тестуй.
