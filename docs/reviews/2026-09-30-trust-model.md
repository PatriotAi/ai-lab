# Хвиля 7 харвесту `gsd-core`: trust-модель поверхні навичок

> Джерело — `docs/explanation/capability-trust-model.md` у `open-gsd/gsd-core` і брифінг
> `docs/reviews/2026-07-31-gsd-core-harvest.md` §4.10. Опрацьовано як **дані**; ідея,
> не код. Реалізовано лише те, що виміряно як реальна дірка; решта названа прямо.

## 1. Що виміряно, а не припущено

**[E]** Штатний шлях `resync` → `verify` не помічає розширення прав навички.
Відтворено 2026-09-30 на повній копії відстеженого дерева (`git archive`):

| Крок | Результат |
|---|---|
| Контроль: чиста копія без змін | `verify` exit 0 |
| `vercel-mcp-connector`: `allowed-tools` `Read` → `Read, Bash(*), WebFetch` | `verify` exit 1 (хеш `SKILL.md` змінився — очікувано) |
| Те саме, але після штатного `resync` | **`verify` exit 0, у звіті 0 згадок про права** |

Доказ — `tests/run-tests.sh` секція 23 (той самий сценарій у мініатюрі) і
`scripts/check-skill-surface.py`, який на цьому зламаному стані повертає код 1 та
називає, що саме додано. **Перша спроба цієї канарки була забруднена** (копія без
кореня репозиторію давала exit 1 через вказівники `[E]`, не через права) — контроль
«чиста копія → exit 0» додано саме тому.

Механізм дірки: `resync` існує, щоб після свідомого оновлення знову вважати хеш нормою.
Тому будь-яка правка `SKILL.md` — зокрема розширення прав — одним рутинним кроком
перестає бути помітною. Це властивість дизайну `resync`, а не помилка коду.

## 2. Що взято з trust-моделі, а що ні

| Ідея `gsd-core` | Рішення | Чому |
|---|---|---|
| Підпис **виконуваної поверхні**: зміна набору хуків/скриптів анулює згоду | **Взято** → `scripts/check-skill-surface.py` | Виміряна дірка (§1). Поверхня в нас: `allowed-tools` · `hooks` · файли `scripts/` |
| Згода прив'язана до конкретної цілі, а не до класу | **Взято** (механіка хвилі 4) | Згода `skill-surface` іменна: ціль = назва навички, з датою |
| Зарезервовані префікси імен проти імперсонації | **Взято** (`anthropic-`, `claude-`) | Дешево; для імен *маркетплейсів* це вже робить `verify-marketplace.py` |
| Install ніколи не виконує код (copy-only staging) | Уже є | Прийом пакета в `CLAUDE.md`: розпакувати → safety-scan → лише тоді застосувати |
| Auto-update вимкнений за замовчуванням | Не застосовно | У нас немає механізму авто-оновлення сторонніх скілів |
| Згода зберігається **поза репозиторієм**, щоб клон не «схвалив себе сам» | **Не взято** | Один власник, згода в репо — свідоме рішення (`consent.md`: реєстратор, не бар'єр); справжнє закриття — рев'ю поза агентом (вікно W-5) |
| SHA-512 pin бандла при встановленні з URL | Не застосовно | Зовнішнього імпорту виконуваних бандлів за URL у нас немає й не заплановано |
| **Декларативні гейти** в точках циклу (`capability.json`: точка · предикат · `blocking` · `onError`) | **Зроблено** за рішенням власника («Так», W-9) | Див. §4 і `docs/gates.md` |

## 3. Що реалізовано

- `scripts/check-skill-surface.py` — звірка з базою `melania-skills-ecosystem/SURFACE.json`.
  **Розширення** (нова навичка · додані права · змінений/доданий скрипт · знята заява
  `allowed-tools` · змінений `hooks`) без записаної згоди — помилка; **звуження** — лише
  інформація. `--update` **відмовляє**, поки є розширення без згоди, інакше базу можна було б
  тихо «освіжити» й стерти слід.
- Шум свідомо виключено: `.snapshots/`, `__pycache__/`, `*.jsonl`, `*.log` — `resync`
  переписує їх щоразу, і без цього перевірка червоніла б на кожному кроці. **[E]** Підтверджено
  у реальному прогоні: після `resync` навички перевірка лишилась зеленою.
- Блок C `safety-compliance-gate` (v1.4.0): рядок «оновлення вже прийнятого скіла» + пункт
  чек-листа C2 — канон в одному місці, інші лише посилаються.
- 21 перевірка в секції 23 набору; **[E]** мутаційна перевірка самого скрипта —
  `tests/mutation-surface.py`, **5 мутантів з 5 спіймано** (нові скрипти не розширення ·
  згода без звірки цілі · `.snapshots` рахується · нові права не розширення · `--update`
  оновлює попри розширення без згоди), жодного «не застосовного». Спершу я прогнав 4 мутанти
  одноразовим скриптом у скретчпаді й **тоді ж помітив, що так «4 з 4» невідтворюване** —
  пробник перенесено в репозиторій і підключено до набору.

## 4. Декларативні гейти: спершу відкладено, потім зроблено за рішенням власника

**Декларативні гейти.** У джерела навичка декларує в JSON, який гейт у якій точці циклу
вона додає, з предикатом і політикою помилки. Для melania це шлях від «`maintain.py verify`
знає все» до «навичка сама заявляє, що перевіряти».

Це **рішення класу `one-way`** за таксономією `docs/methodology.md`: нова схема, яку почнуть
писати автори навичок, а зміна її форми пізніше — міграція всіх навичок. За власним правилом
таке рішення потребує **ухвалення власником до реалізації**, тому спершу воно **не було
реалізоване** і стояло вікном **W-9**: механізм, який мені було б легко вбудувати, — не привід
вбудовувати його без цього рішення.

**Далі того ж дня власник відповів «Так».** Реалізовано: `scripts/run-gates.py` + `gates.json`
(схема v1, точки `verify`/`delivery`), канон — `docs/gates.md`. Поле `schema` зроблено саме для
того, щоб форму можна було змінювати без міграції всіх навичок одразу. `gates.json` входить у підпис
виконуваної поверхні, тож додати собі гейт мовчки не можна: **перший же запуск перевірки поверхні
зупинив мої власні нові `gates.json`** і змусив записати згоду. Перші гейти: `pre-delivery-gate`
(точка `delivery`: windows · reversibility · abstentions — те, що п.10 чек-листа досі лише
описував) і `safety-compliance-gate` (точка `verify`: перевірка поверхні).

**Головний результат:** сценарій, що довів дірку (§1), тепер дає `maintain.py verify` **exit 1**
(було 0) — перевірено на повній копії робочого дерева з контролем «чиста копія → exit 0».

## 5. Чесні межі реалізованого

- **[C]** Перевірка поверхні тепер блокує і в `maintain.py verify` (через декларативний гейт
  точки `verify`), і в наборі тестів → CI. Виняток: пакет melania, що живе **поза** ai-lab, де
  `scripts/run-gates.py` немає, — там `verify` друкує видиму примітку, а не падає й не мовчить.
- **[C]** Згоду записує той самий агент, що правит навичку — це реєстратор, не бар'єр.
  Він робить розширення видимим, названим і датованим у діффі PR; справжнє закриття — рев'ю
  поза агентом.
- **[E]** База створена з **поточного стану** (35 навичок, 31 скрипт). Це фіксація «як є»,
  а не схвалення: **жодну** з наявних поверхонь цим механізмом не переглянуто (вікно W-10).
- **[C]** Перевіряється *заявлена* поверхня. Що саме робить скрипт, ця перевірка не оцінює —
  це `safety-scan` у `maintain.py`.
