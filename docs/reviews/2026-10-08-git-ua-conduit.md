## 0. Головне одним абзацом

проксі середовища (див. §1), тому «багато інших цікавих речей» з каналу **не досліджено**.

скіла **не потрібно**, а з ідей є три реально корисні, і дві з п'яти очевидних — у нас
**вже реалізовані**.

## 2. Що таке conduit (факти)

- **[C]** Нативний Flutter-клієнт (iOS/Android) для Open WebUI, прямих OpenAI-сумісних
  endpoint'ів, Ollama, OpenRouter, Apple On-Device/Private Cloud Compute і self-hosted
  агентів Hermes. Зараз ~2,26 тис. зірок, ~251 форк, активний (оновлено 2026-10-08) —
  за відповіддю пошуку репозиторіїв GitHub; пост каналу називає 2,2 тис. / 248 — збігається.
- **[C]** **Ліцензія GPL-3.0** — прочитано заголовок `LICENSE` у клоні. **Пост каналу про
  ліцензію не згадує взагалі** — а це єдиний факт, що вирішує, чи можна щось брати.
- **[C]** Чати зберігаються на пристрої; ключі й заголовки — у Keychain/Keystore; без
  сторонньої аналітики; «очищення всього» за їхнім описом **безпечно відмовляє, а не
  видаляє наполовину**.
- **[C]** Direct-підключення: OpenAI-сумісні (Chat Completions **або Responses**),
  LM Studio, Azure-стиль версій API, нативний Ollama, OpenRouter; налаштування
  «перевірити з'єднання → увімкнути → вибрати знайдену модель»; довільні заголовки.
- **[C]** Робота за reverse-proxy (`oauth2-proxy`, Authelia, Authentik, Cloudflare Tunnel)
  через збереження потрібних cookie й заголовків на пристрої.
- **[C]** UI показує лише те, що сервер **заявляє** як доступне.
- **[?] Hermes: «схвалення чутливих кроків перед запуском».** README це стверджує, але в
  клієнтському коді я знайшов лише діалоги підтвердження видалення (завдання, MCP) —

## 4. Чесні межі PWA проти нативного клієнта (до пункту 4)

- **[C]** HTTPS-сторінка не може звертатись до `http://` endpoint'у (змішаний вміст) —
  локальний Ollama/LM Studio у домашній мережі напряму недосяжний; потрібен HTTPS-тунель
  або проксі. Це та сама межа, що вже описана для `content://` проти HTTPS у
  `pwa-to-android-app`.
- **[C]** Браузерний запит до Ollama потребує дозволу походження (CORS) на боці сервера.
- **[?] Чи це працює саме в нашому PWA на телефоні.** **бракує:** прогону на реальному
  пристрої з реальним Ollama; у контейнері його нема. До прогону пункт 4 — лише
  попередження в README, а не обіцянка «працює».
- Нативний клієнт (як conduit) цих двох меж не має — і це справжня відповідь на питання
  «PWA чи нативно?», а не привід переписувати mobile-agent.

## 5. Що дізналися про сам процес «канал → репозиторій»

Формат поста (опис · можливості · стек · зірки · форки · платформа) **опускає два факти,
від яких залежить рішення про інтеграцію:** ліцензію і дату останнього коміту. Для
conduit саме ліцензія (GPL-3.0) перекреслила головну спокусу — брати код. Тому для
каналів-агрегаторів пропоную тріаж із шести кроків: (1) пост — лише **вказівник**, не
доказ; (2) репозиторій існує й не архівований; (3) **ліцензія** — копілефт (GPL/AGPL)
означає «лише ідеї»; (4) остання активність; (5) скан README; (6) клон — у окрему
порожню теку, скрипти читають його з `python3 -I`. Вердикт — брифінгом за §4.
