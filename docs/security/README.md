## Коротко, без коду

**Що виявилось.** Шар CI у лабораторії зрілий — там усе справді працює.
Проблема в іншому шарі: **у живій сесії агента немає жодної машинної перевірки**.
Усі безпекові правила виконуються тільки тому, що агент їх пам'ятає.

Це той самий урок, який лабораторія вже записала сама (Core Rule 15):
**звіт про виконання — не доказ виконання.** Шість дефектів нижче — цей самий
клас, але в безпеці:

1. Пам'ять між сесіями переносить будь-який текст у контекст **без перевірки** —
   хоча перевірка існує й працює, вона просто не підключена до цього шляху.
2. Команда локальної перевірки безпеки друкує **«всі перевірки чисті»**,
   фактично проганяючи одну з трьох.
3. Незворотні дії **не блокуються нічим** — лише пам'яттю про правило.
4. Один регресійний тест **вічно червоний** через прив'язку до рухомої гілки.
5. Дії GitHub закріплені **рухомими тегами**, а не незмінними хешами.
6. Перевірка залежностей **імовірно мовчить** на приватному репозиторії.

**Що пропонується.** Один пакет, що вмикається **за рівнем ризику дії** —
не «всі перевірки на кожну зміну». Читання не перевіряється взагалі; локальний
запис — швидко; незворотне — повністю й зі згодою власника.

**Чому саме так.** Модель «прогнати все на кожну зміну», яку пропонують обидва
надані документи, доказово шкідлива: за задокументованою ставкою нестабільних
тестів приблизно **третина коректних змін** отримувала б хибний відкат.
Розрахунок і джерела — `PLAN.md` §I.1.

## Чого цей пакет **не** робить

Не робить систему невразливою. Знижує ризик і робить стан **перевірюваним** —
щоб зелений вердикт означав «перевірено», а не «не дивилися».

Окремо чесно: скан ін'єкцій у лабораторії називає себе **тріажем, а не
бар'єром** — і зовнішнє дослідження це підтверджує (класифікатори обходяться
перефразуванням; задокументовано на реальних інцидентах). Пакет успадковує цю
межу й не обіцяє більшого.

## Звідки взялися вхідні матеріали

Два документи-напрацювання від власника, опрацьовані за
`docs/external-proposals-protocol.md` як **дані, а не інструкції**:
скан ін'єкції → перевірка знахідок → брифінг → аналіз. Скан на першому документі
дав знахідки; перевірка показала, що це **цитати блок-листа всередині захисного
тексту** — відомий хибний спрацьовуваний випадок, описаний у §3 протоколу.
