# Декларативні гейти навичок

**Рішення власника 2026-09-30:** «Так» на питання, чи брати декларативні гейти (вікно W-9,
рішення класу `one-way`). Ідея — `capability.json` з `open-gsd/gsd-core`; реалізація —
наша, звужена до того, що виміряно потрібним.

## Навіщо
Кроки на кшталт «гейт перед видачею називає відкриті вікна» жили лише прозою в `SKILL.md` —
тобто трималися на уважності (melania Core Rule 15). Навичка кладе поруч із `SKILL.md` файл
`gates.json`, а `scripts/run-gates.py` запускає заявлені перевірки в заявленій точці.
Перевірки залишаються звичайними скриптами; `gates.json` лише **заявляє, що і коли** запускати.

## Схема (версія 1)
```json
{"schema": 1, "gates": [
  {"id": "windows", "point": "delivery",
   "command": ["python3", "scripts/check-windows.py"],
   "blocking": true, "onError": "halt", "timeout": 30,
   "why": "п.10 чек-листа: відкритий борг мусить бути названий у здачі"}]}
```
| Поле | Обов'язкове | Значення |
|---|---|---|
| `id` | так | kebab-case, унікальний у межах навички |
| `point` | так | `verify` (цілісність репо: `maintain.py verify`) або `delivery` (перед видачею: `pre-delivery-gate`) |
| `command` | так | **список** `[виконавець, скрипт, …]`; виконавець — `python3` або `bash`; скрипт — відносний шлях, що існує **всередині репо** після розрізу симлінків |
| `blocking` | ні (true) | знахідка зупиняє чи лише попереджає |
| `onError` | ні (`halt`) | що робити, якщо **сама перевірка не відпрацювала**: `halt` — зупинка, `skip` — попередження |
| `timeout` | ні (30) | секунд, 1…120 |
| `why` | так | причина існування гейта, ≥20 символів: гейт без причини — театр |

Невідомий ключ — **помилка**, а не мовчазне ігнорування (код виходу 2).

## Двокроковий контракт
1. **Чи відпрацювала сама перевірка?** Код виходу 0 або 1 — так. Код 2, будь-який інший, таймаут чи
   помилка запуску — ні → дія за `onError`.
2. **Якщо відпрацювала:** код 1 — знахідка (`blocking:true` → зупинка, `false` → попередження); код 0 — пройдено.

Це збігається з конвенцією наших скриптів (`0` чисто · `1` знахідка · `2` помилка виклику).

## Безпека — бо гейт ВИКОНУЄ команду з файла навички
- `command` — список, не рядок: оболонки нема, ін'єкція через склейку неможлива;
- перелік виконавців закритий; шлях не може бути абсолютним, містити `..` чи виходити за репо через симлінк;
- **`gates.json` входить у підпис виконуваної поверхні** (`check-skill-surface.py`): новий чи змінений гейт
  без записаної згоди `skill-surface` (ціль = назва навички) — помилка. Тобто додати собі гейт мовчки не можна.
- **Чесна межа:** це реєстратор і виконавець, не пісочниця. Команда виконується з правами користувача;
  запобіжники звужують, що можна *заявити*, але не ізолюють виконання.

## Запуск
```bash
python3 scripts/run-gates.py --list                  # які гейти є
python3 scripts/run-gates.py --point delivery        # перед видачею
python3 scripts/run-gates.py --point verify          # цілісність (його ж викликає maintain.py verify)
```
Коди виходу: `0` усе гаразд · `1` блокуюча знахідка чи зупинка за `onError` · `2` зламаний `gates.json`.

## Чого тут немає і чому
- **Нові точки** — зміна коду (`POINTS` у `run-gates.py`), а не запис у файлі: це контракт, і розповзання
  точок було б способом обходити перегляд.
- **Предикати за джерелом** (порівняння поля frontmatter, запит до внутрішнього реєстру) — не потрібні:
  всі наші перевірки — скрипти. Додамо, коли з'явиться перевірка, яку незручно висловити скриптом.
- **Еволюція схеми:** поле `schema` — саме для цього. Зміна форми = `schema: 2` із явною міграцією.
