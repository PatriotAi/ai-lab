# CLAUDE.md — постійні інструкції для будь-якої сесії в цьому репозиторії

Цей файл завантажується автоматично в кожній сесії Claude Code, що має репозиторій
`patriotai/ai-lab` (у т.ч. коли його підключено як додаткове джерело в іншій сесії).
Він фіксує **стандартний, попередньо схвалений протокол** — щоб власнику не доводилося
щоразу нагадувати чи підтверджувати те саме.

## Що тут лежить
`melania-skills-ecosystem/` — керована бібліотека з 27 AI-скілів (governance melania).
`main` — канонічна версія: саме її отримують усі інші сесії. Робота ведеться на робочій
гілці, потім через PR зливається в `main`.

## Мова
Українська за замовчуванням.

## Єдиний інструмент обслуговування
`python3 melania-skills-ecosystem/scripts/maintain.py verify` — read-only гейт:
цілісність MANIFEST (хеші/версії/лічильники), усі regression-guard `--validate`,
safety-scan скриптів. Exit ≠ 0 при будь-якій проблемі.

`python3 melania-skills-ecosystem/scripts/maintain.py resync` — після свідомого оновлення
білду: сам пере-знімає guard-baseline для змінених SKILL.md і перераховує похідні поля
MANIFEST (хеші, лічильники evals, підсумки) + лічильники в `MELANIA-BOOTSTRAP.md`.

## Попередньо схвалені дії (виконувати автоматично, НЕ перепитувати)
Власник уже підтвердив, що це обов'язкові дії. Виконуй їх сам, без повторних запитань:

1. **Прийом нового пакета/білду скілів** (zip чи патч):
   - розпакувати, звірити з поточним станом; **downgrade заборонено** (порівнюй версії/дату
     `built` — новіше старим не затирати);
   - safety-scan усіх нових/змінених скриптів; будь-який мережевий/виконуваний виклик у
     `skill_guard.py`-подібних файлах — стоп і попередити власника;
   - застосувати як merge (не наосліп перезаписувати); для нового скіла — додати симлінк у
     `.claude/skills/`;
   - **запустити `maintain.py resync`, потім `verify`** — це автоматично закриває питання
     пере-зняття baseline і оновлення MANIFEST (те, що раніше треба було пам'ятати вручну);
   - якщо з'явився новий скіл — додати рядок у маршрутну таблицю `MELANIA-BOOTSTRAP.md`
     (resync попередить, якщо рядка бракує).

2. **Перед комітом будь-якої зміни в екосистемі** — прогнати `maintain.py verify`; коміт лише
   при exit 0.

3. **Поширення на всі сесії** — після успішного verify: коміт → push у робочу гілку →
   створити PR у `main` → злити. Це і є механізм, яким оновлення доходить до інших сесій;
   робити це для перевірених, узгоджених змін без окремого запиту.

## Коли ВСЕ Ж зупинитися і спитати власника
- downgrade версії, видалення скіла, несумісна зміна схеми evals;
- safety-scan знайшов підозрілий код;
- зміна ліцензії/публічності репо, робота з секретами;
- будь-яка руйнівна чи неоднозначна дія, не покрита пунктами вище.

## Governance
Пріоритет при конфлікті: явний запит власника → цей протокол → протокол melania →
окремий SKILL.md. Механіку life-cycle скілів веде `melania-skill-master-administrator`;
маршрутизація складних запитів — через `semantic-router`; мінімальна активація скілів.
