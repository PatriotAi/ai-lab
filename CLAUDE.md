# CLAUDE.md — контекст лабораторії

Це особиста **лабораторія продуктивності** (ai-lab). Працюємо з багатомовними
(UA/EN) проєктами та AI-автоматизаціями. Мета — створювати, покращувати,
спрощувати й винаходити робочі процеси. Окремі напрацювання зберігаються як
зразки в `projects/` і згодом можуть виноситися в самостійні репозиторії.

Цей файл завантажується автоматично в кожній сесії Claude Code, що має репозиторій
`patriotai/ai-lab` (у т.ч. коли його підключено як додаткове джерело в іншій сесії).
`main` — канонічна версія: саме її отримують усі інші сесії.

## Мова
- Спілкування з користувачем — **українською**.
- Документи — українською (ключові терміни дублюй англійською).
- Артефакти для публікації — двомовні UA/EN, якщо не вказано інше.
- **Вихід зовнішніх інструментів (дослідження, веб-пошук, tool-результати) перекладати
  українською перед включенням у відповідь** — не вставляти англомовний підсумок дослівно.

## Структура репозиторію
- `docs/` — методологія, дорожня карта, план (PLAN), журнал висновків, глосарій; білінгвальний онбординг у `docs/ua` + `docs/en`
- `projects/` — самостійні проєкти-зразки (шаблон: `projects/project-template/`)
- `experiments/` — маленькі експерименти-гіпотези (кожен: тека з README)
- `skills/` — індекс навичок (канонічні SKILL.md версіоновані в `.claude/skills/<name>/`)
- `melania-skills-ecosystem/` — керована бібліотека AI-навичок (governance melania); активні через симлінки в `.claude/skills/`
- `automations/` — хуки/скрипти/пайплайни (джерело; активуються через `.claude`/settings)
- `scripts/` — допоміжні утиліти
- `templates/` — шаблони
- `security/` — конфіги безпеки (Trivy); політика — `SECURITY.md`
- `.github/` — CI (security, code-quality, dependencies), CODEOWNERS, Dependabot, шаблони Issue/PR

## Методологія
Експеримент-орієнтована: **гіпотеза → дизайн → запуск → вимір → лиши/прибери → висновок**.
Деталі — `docs/methodology.md`.

## Конвенції
- Кожна нова навичка/автоматизація = окрема тека з коротким README/SKILL.md.
- **Одна автоматизація — одна відповідальність.**
- **Тригери навичок — за значенням запиту (semantic match):** навичка активується,
  коли намір збігається за змістом, навіть якщо сформульований іншими словами;
  фрази-приклади в описах не є вичерпним списком (директива власника 2026-07-19).
- **Жодних секретів у репозиторії** — токени лише через env-змінні (`.env`, ігнорується).
- Перед комітом ганяй `pre-commit`; CI перевіряє секрети (gitleaks), вразливості
  (Trivy) і SAST (Semgrep).
- Перед великими/незворотними змінами — спершу план (plan mode).
- Що лишаємо після експерименту — виносимо в багаторазову навичку/автоматизацію
  і записуємо висновок у `docs/learnings.md`.

## Обслуговування бібліотеки Melania
Бібліотека `melania-skills-ecosystem/` має власний протокол обслуговування.

**Інструмент цілісності:**
- `python3 melania-skills-ecosystem/scripts/maintain.py verify` — read-only гейт:
  цілісність MANIFEST (хеші/версії/лічильники), усі regression-guard `--validate`,
  safety-scan скриптів. Exit ≠ 0 при будь-якій проблемі.
- `python3 melania-skills-ecosystem/scripts/maintain.py resync` — після свідомого
  оновлення білду пере-знімає guard-baseline для змінених SKILL.md і перераховує
  похідні поля MANIFEST + лічильники в `MELANIA-BOOTSTRAP.md`.

**Попередньо схвалені дії (виконувати без окремого запиту):**
1. Прийом нового пакета/білду навичок: розпакувати й звірити (**downgrade заборонено** —
   новіше старим не затирати); safety-scan усіх нових/змінених скриптів (будь-який
   мережевий/виконуваний виклик → **стоп і спитати власника**); застосувати як merge;
   для нового скіла — симлінк у `.claude/skills/`; `maintain.py resync`, потім `verify`;
   оновити рядок у `MELANIA-BOOTSTRAP.md`.
2. Перед комітом будь-якої зміни в екосистемі — `maintain.py verify`; коміт лише при exit 0.
3. Підготовка поширення: коміт → push у робочу гілку → **відкрити PR у `main`**.

> **Межа автоматики:** пре-схвалення діє максимум до *відкриття PR*. Саме **злиття (merge)
> у `main` — лише за явною згодою власника** (див. нижче). Це узгоджує протокол Melania з
> правилами лабораторії «одна автоматизація — одна відповідальність» і «незворотні дії —
> лише за згодою власника».

## Коли ЗУПИНИТИСЯ і спитати власника
- **злиття (merge) будь-якого PR у `main`;**
- downgrade версії, видалення навички, несумісна зміна схеми evals;
- safety-scan знайшов підозрілий код;
- зміна ліцензії/публічності репо, робота з секретами;
- будь-яка руйнівна чи неоднозначна дія, не покрита пунктами вище.

## Governance
Пріоритет при конфлікті: **явний запит власника** → правила лабораторії (цей файл) →
протокол melania → окремий SKILL.md. Механіку life-cycle навичок веде
`melania-skill-master-administrator`; маршрутизація складних запитів — через
`semantic-router`; **мінімальна активація навичок** (не всі одразу).
